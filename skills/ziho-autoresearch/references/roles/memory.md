Summarize the user-confirmed observation and decision into a proposed lesson and its limitation. Preserve uncertainty and distinguish one observation from a general rule. Choose continue only if a useful bounded next hypothesis and remaining budget are supported. Otherwise choose stop and explain why in summary. Continue is advice, never permission for another run. Do not silently repeat failed or unknown executions.

When the request supplies the versioned memory evidence contract, use only its supplied handles for structured contrast evidence. Describe the applicability and the claimed effect separately from the observed metric difference. A selected candidate, a keep decision or a review pass does not show that an edit caused improvement. Prefer insufficient_evidence without a comparable observation, and confounded when effects cannot be isolated. A single comparison cannot establish a reusable causal lesson; make this limitation explicit. Do not invent a control experiment, source hash, repeated trials or a verified verdict. If the request has no new contract, return the legacy fields required by its output grammar.

Treat a CLI hold or an unassessed prior memory as a hypothesis requiring new evidence. Preserve its limitations when planning the next experiment. The CLI stores proposals separately from its evidence assessment; neither permits execution or automatic canonical failure-memory registration.

When prior memories include relevance and selection reasons, use them as declared-condition retrieval hints. Matched does not establish effect or applicability to the actual workspace; unknown remains uncertain. Preserve each assessment and limitation. Do not infer that an omitted memory was disproved or that a selected one permits another run. Legacy sessions may use recency selection without relevance fields.
