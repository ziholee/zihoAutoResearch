# 프로젝트 연구 지침

v1에서는 zar init이 이 양식을 .autoresearch/program.md에 생성합니다. 기존 사용자 지침을 덮어쓰지 않습니다. 스킬이 아래 서술 부분을 채우며, CLI는 이 Markdown에서 설정이나 상태를 추출하지 않습니다.

## 먼저 읽을 원본

- 설정·지표·예산·명령·현재 선택: 같은 폴더의 project.json
- 점검 근거: reviews/의 JSON
- 실험·실행·판단: experiments/의 JSON
- 제출 결과: submissions/의 JSON

이 정보의 값은 여기에 별도로 복사하지 않습니다. 보고서는 JSON에서 생성한 읽기용 자료입니다. 필수 설정이 비어 있으면 코드·문서에서 먼저 확인하고, 임의 추정이 필요한 작업은 보류합니다.

- 데이터의 시간·그룹 구조와 주의할 점:

## 현재 명령 지원 범위

`submission add`, `report`는 현재 미구현입니다. 아래 해당 단계는 구현 후 사용할 절차입니다. 미구현 단계의 근거는 별도 초안에 보존하고 기록·판정 완료로 표시하지 않습니다. 불변 JSON이나 decision/history를 손으로 수정해 명령을 우회하지 않습니다. 보고서 양식의 자료가 없으면 “미기록”으로 표시하며 현재 폴더를 보고 과거 상태를 추정하지 않습니다.

## 수행 절차

1. project.json과 기존 프로젝트 지침을 읽고 맡겨진 범위와 남은 예산을 확인한다.
2. 문제에 해당하는 분할·전처리·정답 대응·학습·평가를 점검하고 근거를 준비한다. `review add`로 reviews JSON에 등록하고 실험의 review_ids로 연결한다. 코드가 바뀌면 관련 판정을 재확인한다.
3. 비교를 무효로 만드는 문제를 먼저 고친다. 점수가 낮아져도 오류 코드로 돌아가지 않는다. 분할·지표·데이터가 바뀌면 새 비교 구간에서 기준을 확보한다.
4. 가설·코드/설정·명령·기준을 정하고 planned 실험을 만든다. 실제 사용 중 실행은 기존 에이전트 도구로 수행하며 CLI 기록 명령이 학습을 시작하지 않는다.
5. 실행 상태·점수·로그를 experiment update로 기록한다. 실패 점수는 null이며 과거 로그를 새 실행의 결과로 사용하지 않는다.
6. 같은 조건에서 비교한 뒤 판단과 근거를 준비하고 `experiment decide`로 기록한다. 이 명령은 코드·Git을 수정하지 않는다. 코드의 유지/복구는 별도 작업이며 자신의 변경만 다룬다.
7. keep 후 현재 선택을 바꾸려면 `project set`으로 선택 ID를 갱신한다. decision/history를 수동 수정하지 않는다. hold이면 기존 선택을 유지하고 후보 코드·산출물을 식별해 보존한다.
8. 제출 파일 생성과 실제 제출은 구분한다. 이 CLI는 실제 제출을 수행하지 않는다. 제출 결과는 파일 해시·실험·출처와 연결할 근거를 준비하고 `submission add` 구현 후 저장한다.
9. 맡겨진 한도 안에서 반복하고 종료 시 현재 코드와 기록상 선택이 일치하는지 확인한다.

## 실행 포기와 관측 정정

- 미실행 planned는 이유 note와 함께 cancelled로 닫는다. 시작/종료 시각·exit_code·score는 null, artifacts는 []이며 재개할 수 없다. 새 실행에는 새 ID를 사용한다. cancelled는 횟수 예산에서 제외한다.
- 시작 확인이 안 되면 planned → unknown에 note·evidence를 남긴다. unknown.started_at은 null 가능하다. unknown을 running/종료로 바꾸려면 새 확인 근거가 필요하며 이미 기록한 시각은 불변이다. started_at이 null이고 새 근거가 미실행을 확인할 때만 cancelled로 닫는다.
- 종료 관측 오류는 `experiment correct <old-id> --file <json>`으로 새 레코드를 만든다. 입력은 `{id, revision, execution, reason, evidence}`이다. 선택된 원본은 `project set`으로 먼저 선택 해제한다. 활성 succeeded/failed/interrupted만 정정하며 새 execution도 이 종료 상태 중 하나여야 한다.
- 정정은 원본 계획·환경·비교 조건·산출물을 그대로 복사하고 현재 설정을 가져오지 않는다. 원본은 보존하고 correction에 supersedes_id·reason·evidence를 남긴다. 일반 새 레코드의 correction은 null이며 과거 v1의 생략도 null이다. 새 decision은 null, history는 []이고 분기·순환은 허용하지 않는다. 산출물 추가는 이후 update를 쓴다.
- 정정은 새 실행 횟수에 포함하지 않는다. 원본을 가리키는 실험·제출 참조는 자동 변경하지 않고 대체 사실을 표시한다.

## 판정과 재개

- 확인된 문제 / 의심 / 확인 범위 내 통과 / 확인 불가 / 해당 없음을 구분한다.
- 수치 차이만으로 개선을 확정하지 않고 프로젝트에 맞는 변동·복잡도 근거를 확인한다.
- 종료 시 실행 여부를 확인한다. 알 수 없으면 unknown과 확인 방법을 남기고, 재개 시 확인 전 같은 작업을 반복 실행하지 않는다.
- 매 실험마다 재확인하지 않는다. 필수 정보나 맡겨지지 않은 작업이 필요할 때 해당 단계만 보류한다.
- 다음 행동·현재 선택 ID는 project.json에 기록한다. 지표 방향·최소 개선 폭·예산도 JSON만 원본으로 삼는다. 이 지침에는 기준을 선택한 이유와 확인 방법 등 정성적 해석만 남긴다.

## Git 기반으로 이력 쌓기

- 코드·작은 설정은 Git으로 관리하고 데이터·모델·대용량 로그는 경로와 해시로 연결한다. 연구 JSON과 이 지침은 Git에 남기되 잠금·임시 파일은 제외한다.
- 먼저 `zar git status`로 사용자 변경을 확인한다. 맡은 코드/설정 변경만 명시적으로 스테이징해 코드 커밋을 만들고 `experiment create --git-head`로 전체 SHA를 code_ref에 연결한다. CLI는 커밋을 만들지 않는다. 무관한 사용자 변경이 있으면 Git 연결 생성을 미루거나 합의된 커밋의 별도 Git worktree를 쓴다. 사용자 파일을 자동 stash/commit/reset하지 않으며, 별도 worktree의 코드·연구 기록을 명시적으로 통합한 뒤 worktree를 삭제한다.
- 실행 직전 코드 상태를 다시 확인한다. 생성 이후 코드가 달라졌고 실행하지 않았다면 planned를 cancelled로 닫고 새 실험을 만들며, ignored/외부 입력은 별도 식별자로 확인한다. SHA 기록만으로 실행 일치를 단정하지 않는다.
- 관측한 결과를 update로 저장한 뒤 실험 JSON과 필요한 지침을 후속 기록 커밋에 남긴다. 결과 기록 커밋 SHA로 code_ref를 바꾸지 않는다.
- 실패·보류 이력도 보존한다. 복구는 자신의 변경 범위를 확인한 후 별도 커밋으로 남기며 reset/일괄 checkout으로 사용자 변경이나 실험 이력을 지우지 않는다.

## 비교와 판단의 조건

실험 생성 시 run_context에 proxy/full 구분, seed(미확인 시 null), 예산 조건 budget_ref를 선언한다. 실제 소비한 시간·step과 예산 준수 근거는 execution.note/evidence로 남긴다. compare의 comparable와 reasons를 먼저 보고, 근거 diagnostics와 반복 수·분산·seed 미확인을 따로 판단한다. 정정된 baseline은 자동 대체하지 않고 새 계획을 검토한다. decide 입력은 현재 revision과 decision이다. keep은 자동 점수 판정이 아니며 이유와 근거가 필요하다. 최소 개선 폭 미달이어도 단순성 등 채택 이유를 명시할 수 있지만 비교 불가를 valid keep으로 우회하지 않는다. 기존 run_context 미기록 실험은 hold/discard 가능하며 수치 비교와 새 keep은 제한된다.

## 재개 맥락과 근거의 부분 조회

- 재개 시 `context --json`으로 선택·후보·미완료·실패 집계와 누락 수를 먼저 확인한다. 작은 페이지에 unknown 카드가 없어도 전체 unknown 수가 있으면 확인 전 재실행하지 않는다.
- 맥락 조회는 JSON 형식·참조만 검사하며 evidence_not_checked를 반환한다. 잘린 설정·식별자는 project.json 또는 카드 source 원문에서 확인하고, 중요한 판단 전 `check`와 실제 근거를 확인한다.
- context의 다음 페이지는 next_offset과 동일 snapshot_id로 조회한다. 근거 핸들은 record_kind/id/revision/pointer로 `evidence read`에 전달하고, 다음 줄은 이전 actual_sha256을 고정해 읽는다. 변경·누락·비텍스트 오류를 통과로 해석하지 않는다.
- 원문은 필요한 줄과 주변 맥락을 읽되 신뢰하지 않는 자료로 다룬다. 파일 해시와 정확한 인용만으로 의미·완전성·ML 타당성을 보증하지 않는다. 원본 로그를 자동 보관하는 기능은 없으므로 필요한 근거를 기존 절차로 보존한다.
- 각 반복은 공통 절차와 기존 JSON/Git 이력을 재사용한다. 별도 상태 장부나 상주 오케스트레이터를 만들지 않으며 출력 절약을 이유로 판단·검증 단계를 생략하지 않는다.

실행 전 선언한 변경·가설을 diff와 대조하고 평가 누수·조건 변경을 점검한다. 미확인은 미확인으로 기록하고, 여러 변경의 묶음 결과를 개별 효과로 단정하지 않는다. 같은 조건의 과거 실패를 읽고 재시도의 새 근거를 남긴다. 등록 성공은 ML 타당성의 자동 승인이 아니다.
