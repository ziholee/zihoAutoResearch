# 승인한 단일 역할 지침 비교

상태: 개발 브랜치 구현 · 미배포. 공개 v0.3.0에는 이 명령이 없습니다. 검증 범위는 모의 공급자의 요청과 로컬 상태 제어이며, 실제 API 연결·추론 품질·청구 비용은 미검증입니다.

이 기능은 진행 중인 연구 세션의 **다음 역할 하나**에 대해 패키지 원본 지침과 사용자가 작성한 변형 지침을 비교합니다. 같은 입력과 연결 프로필을 사용해 응답을 나란히 기록하며, 승자를 정하거나 변형을 설치하지 않습니다. 실험 결과를 비교하는 기능은 아닙니다.

## 준비하고 승인하기

먼저 [연구 세션](research-api.md)을 생성합니다. 비교 준비가 가능한 부모 상태는 `planning`, `observed`, `remembering`이며, 아직 응답이 없는 다음 역할을 자동으로 선택합니다. `planning`은 분석부터 시작하는 계획 단계 전체의 상태 이름입니다. 항상 설계 역할만 선택한다는 뜻은 아닙니다.

프로젝트 안에 UTF-8 변형 파일을 작성합니다. 파일에는 해당 역할의 **전체 대체 지침**을 넣습니다. 공통 응답 형식과 도구·실행 제한은 그대로 유지됩니다. 파일은 비어 있지 않아야 하며 최대 65,536바이트입니다. 숨김 경로와 심볼릭 링크는 허용하지 않습니다.

```sh
zar research variant-prepare SESSION_ID --file variants/analysis.md \
  --project ./my-ml-project --json
zar research variant-status VARIANT_ID --project ./my-ml-project --json
```

`--file`은 프로젝트 상대 경로입니다. 준비 결과의 `id`가 별도 `VARIANT_ID`이며 부모 세션 ID와 다릅니다. 준비는 공급자를 호출하지 않습니다. 부모는 `comparing`으로 잠기고 비교 기록은 `awaiting_approval`이 됩니다.

출력의 `bundle`에서 선택된 `role`, 원본·변형 지침, `instruction_hashes`, `context`, `profile`, 실제 두 `messages`를 확인합니다. 입력·프로필·묶음 해시와 승인 토큰도 고정됩니다. 변형 지침뿐 아니라 전송할 소스·기록·이전 응답을 함께 검토한 뒤 승인합니다.

```sh
zar research variant-approve VARIANT_ID --token APPROVAL_TOKEN \
  --project ./my-ml-project --json
zar research variant-advance VARIANT_ID --send \
  --project ./my-ml-project --json
```

승인과 전송은 별도 단계입니다. 승인하지 않았거나 `--send`가 없으면 호출하지 않습니다. 비교가 끝나거나 취소될 때까지 부모의 일반 `advance`·실행 절차로 우회할 수 없습니다.

## 고정되는 조건과 호출 예산

원본을 먼저, 변형을 다음으로 한 번씩 호출합니다. 두 요청의 사용자 입력, 모델 및 연결 프로필은 같습니다. 역할별 지침만 다르며, 부모 세션의 호출 예산에서 각 시도 직전에 한 회씩 차감합니다. 준비에는 최소 두 회의 남은 호출 예산이 필요합니다. 별도 무료 호출이나 자동 재시도는 없습니다.

각 요청에는 동일한 프로필 시간 한도와 해당 공급자의 출력 제한을 적용합니다. 남은 세션 시간이 고정된 요청 시간 한도보다 짧으면 호출을 거부합니다. 후반 요청만 시간 한도를 줄여 비교하지 않습니다. 동일한 조건을 지정해도 공급자의 비결정성이나 고정된 호출 순서에 따른 영향을 제거한 것은 아닙니다.

승인과 각 호출 전후에 부모 설정·소스·기록·선택된 세션 기억의 입력, 변형 파일, 현재 패키지 역할 지침을 다시 확인합니다. 승인 이후 내용이 달라지면 기존 승인으로 계속하지 않습니다. 변경 원인을 확인하고 취소한 뒤 새 비교를 준비합니다. 해시는 입력의 일관성을 확인하며 외부 공격에 대한 서명이나 연구 효과의 증명이 아닙니다.

요청 묶음은 2MiB 미만, 결과를 포함한 비교 기록은 최대 4,000,000바이트입니다. 상한 초과는 저장·처리 오류가 될 수 있으므로 출력 한도도 제한하세요. 원본 입력과 응답이 로컬 `.autoresearch/variants/`에 저장되므로 민감한 자료를 포함하거나 공개 커밋하지 않도록 확인합니다.

## 결과 읽기와 원래 루프로 돌아가기

`variant-status`에서 `arms.original`과 `arms.variant`의 응답·상태·측정을 확인합니다. 응답 형식과 해당 역할의 근거·수정 범위를 검증한 경우 `validated`, 거부된 응답은 `invalid`, 결과가 확정되지 않은 호출은 `unknown`으로 남습니다. `validated`는 응답 계약 통과이며 사실성이나 실험 효과 검증이 아닙니다.

완료 요약은 항상 `hold`, `automatic_selection: false`입니다. 정상 응답 둘의 동일 여부·변경 필드를 보여주며, 불완전하거나 잘못된 쌍도 효과 판정을 보류합니다. 기억 역할의 기존 보류 규칙도 유지됩니다. 측정은 관측된 시간·전송 준비 크기·공급자가 보고한 토큰을 뜻하며, 누락 토큰이나 금액을 추정하지 않습니다.

비교가 끝나면 부모는 이전 상태로 돌아가지만 부모의 `outputs`에는 어느 응답도 채택하지 않습니다. 원래 루프를 이어가려면 명시적으로 `research advance SESSION_ID --send`를 실행합니다. 해당 역할을 원본 지침으로 다시 호출하므로 추가 예산이 필요합니다. 비교 승인 토큰은 실험 실행 승인으로 재사용할 수 없고, 코드 적용·명령 실행에는 원래 승인 절차가 그대로 필요합니다. 구버전 부모에 새 기억 계약이나 선택 버전을 강제로 추가하지 않습니다.

## 중단·복구·취소

```sh
zar research variant-status VARIANT_ID --project ./my-ml-project --json
zar research variant-recover VARIANT_ID --confirm-stopped \
  --project ./my-ml-project --json
```

`calling` 또는 `unknown`이면 먼저 이전 CLI와 공급자 프로세스가 실제로 종료했는지 확인합니다. `--confirm-stopped`는 사용자의 확인이며 프로세스가 끝났다는 자동 증거가 아닙니다. API 서버가 이미 요청을 처리했을 수도 있습니다.

복구는 시도했던 응답을 `unknown`으로 보존하고 재전송하지 않습니다. 아직 시도하지 않은 `pending` 요청만 다음 `variant-advance --send`로 보낼 수 있습니다. 모든 요청을 이미 시도했다면 결과를 정리하며 다시 호출하지 않습니다. 부모의 호출 예산도 되돌리지 않습니다. 호출 직전 중단이면 실제 전송 없이 예산이 차감됐을 가능성도 보수적으로 유지합니다.

```sh
zar research variant-cancel VARIANT_ID --project ./my-ml-project --json
```

`awaiting_approval`, `approved`, `blocked` 상태에서 취소하면 부모를 이전 상태로 돌려보냅니다. `calling`·`unknown`에서는 먼저 종료 확인과 복구가 필요합니다. 취소는 이미 보낸 요청을 회수하거나 관측을 성공으로 바꾸지 않습니다. 부모의 실제 실험이 중단된 경우에는 이 비교 복구 명령이 아니라 [기존 실행 복구 절차](research-api.md)를 사용합니다.

응답 처리 중 세션 마감을 넘으면 비교는 `blocked`·`hold`로 남습니다. 결과를 확인하고 `variant-cancel`로 부모를 해제할 수 있지만, 부모의 기존 마감은 연장되지 않습니다.

완료 또는 취소 기록 저장 뒤 부모 복귀 전에 프로세스가 종료됐다면, 부모가 여전히 `comparing`일 수 있습니다. 이전 프로세스 종료를 확인한 뒤 같은 비교 ID에 `variant-recover --confirm-stopped`를 사용하면 요청을 재전송하지 않고 부모 잠금 해제를 마칩니다.

## 검증 범위

모의 HTTP와 새 CLI 프로세스로 승인·전송 동의, 동일 입력·모델·출력 한도, 부모 예산 차감, 변경 감지와 구버전 재개를 확인합니다. 실제 CLI 강제 종료 후 원본 요청을 재전송하지 않고 미시도 변형만 호출하는 검사도 포함합니다. 합성 baseline 실행 뒤 해석·기억 역할 비교는 결과 미채택과 `hold`를 유지하며 기존 승인 루프로 복귀합니다. 완료 기록 저장 후 부모 복귀 중 저장 실패도 재호출 없이 복구합니다. 이 검증은 실제 모델의 판단 품질이나 지침 효과를 평가한 결과가 아닙니다.
