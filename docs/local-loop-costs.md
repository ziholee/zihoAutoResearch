# 로컬 실험 루프 비용 분해

2026-10-20 · 개발 소스용 측정이며 공개 v0.3.0의 기능 안내가 아닙니다.

같은 합성 회귀 데이터로 기준 실험과 후보 실험을 실행하고, 후보 관측 직후 프로세스를 종료한 뒤 새 프로세스에서 판단을 이어갑니다. 기존 [도구 효용 비교](workflow-utility-comparison.md)의 zar 경로와 산출물 검증기를 재사용합니다. 실제 모델이나 외부 API는 호출하지 않습니다.

## 측정 범위

CLI는 매번 새 프로세스로 실행합니다. 계측용 실행기는 기록 로딩, 지정된 검증 함수, 원자적 저장, 내부 Git 호출을 감싸며 중첩된 호출 시간은 자식 범주에 한 번만 배분합니다. 예를 들어 기록 로딩 중 문서 검증 시간은 기록 로딩에서 빼고 검증에 넣습니다. 지정된 함수 밖의 검사, 잠금, 학습 대기, 모의 공급자 대기 등은 나머지 CLI 시간에 포함됩니다. 저장의 `fsync`, 잠금, 신선도 검사나 승인 단계를 생략하지 않습니다.

CLI 시작 시간은 부모의 프로세스 실행 직전부터 계측 실행기의 `main` 호출 직전까지입니다. Python 시작·import·계측 준비가 포함되며 순수 제품 import 시간으로 해석할 수 없습니다. 계측 실행기를 사용하지 않는 대조 실행과 전체 시간을 비교합니다. 이 차이는 계측 비용뿐 아니라 실행기·모듈 선행 import 차이와 일상적인 측정 변동을 포함하므로 순수 계측 오버헤드로 분리된 값은 아닙니다.

외부 Git 명령과 CLI 내부 Git 명령은 구분합니다. Git 커밋 이정표 이벤트는 여러 Git 명령을 포괄하므로 시간 합계에 다시 넣지 않습니다. 모의 HTTP 응답 시간 역시 CLI 대기와 겹치므로 합산하지 않습니다. 모의 서버 종료 대기는 제품의 추론·학습 시간이 아닙니다.

계측 대상 검증 함수는 `validate_document`, `inspect_project`, `validate_response`, `validate_profile`입니다. 주 스레드만 배타 집계하며 배경 스레드에서 일어나는 작업은 주 스레드의 대기를 통해 나머지 시간에 포함됩니다. 시작 진단의 Python 실행기 진입·준비 시간은 시작 시간 안에 포함되므로 다시 더하지 않습니다. 프로세스 종료·계측 결과 쓰기·타이머 장부 비용의 잔여 시간도 별도로 남깁니다.

## 재현과 적용

개발 소스를 설치한 Python 3.11 이상과 Git이 필요합니다. 출력은 존재하지 않는 새 디렉터리여야 합니다.

```sh
python -m pip install .
python scripts/benchmark_local_loop_costs.py --output ./local-costs --repeats 3
```

각 반복은 기본 실행(종료 확인 간격 0.5초), 계측 실행(0.5초), 짧은 종료 확인 간격 실행(0.01초)을 모두 수행하며 순서를 순환합니다. 워밍업이나 캐시 초기화는 하지 않습니다. `summary.json`은 숫자·범주·코드 해시를 담고, 각 실행의 하위 폴더에는 로컬 원본 기록과 Git 저장소가 남습니다. 원본 폴더는 로컬 경로가 포함될 수 있으므로 공개용 보고서와 구분합니다. 코드 해시는 스크립트와 함께 있는 소스의 해시이므로 성능 비교 시 설치본도 해당 소스와 일치시켜야 합니다.

확인된 변경은 `benchmark_workflow_utility.py`의 모의 서버 기본 확인 간격을 0.5초에서 0.01초로 줄인 것입니다. 종료 시 `shutdown`, `server_close`, 스레드 종료 확인은 유지합니다. 더 잦은 확인에는 CPU 깨우기 비용이 있을 수 있고 CPU 사용량은 측정하지 않았습니다. 제품의 학습·추론이나 실제 공급자 속도 개선이라고 주장하지 않습니다. 이 비용 분해 스크립트는 이전 0.5초 설정을 명시하여 계속 재현합니다.

## 로컬 측정 결과

macOS arm64, Python 3.11.17에서 회귀·빌드·설치 검사를 끝낸 뒤 각 조건을 3회씩 직렬 실행한 중앙값입니다. [원자료](benchmarks/local-loop-costs-results.json)에 개별 시행, 순서, 계측 호출 수와 소스 해시를 보관합니다. 단일 환경의 관측이며 모든 배경 부하를 통제한 결과는 아닙니다.

| 전체 루프 범주 | 기본 실행 | 계측 실행 | 종료 대기 개선 |
|---|---:|---:|---:|
| 전체 | 2.239초 | 2.284초 | 1.632초 |
| CLI 20회 | 1.322초 | 1.373초 | 1.315초 |
| 외부 Git 13회 | 0.183초 | 0.183초 | 0.179초 |
| 모의 서버 종료 2회 | 0.579초 | 0.556초 | 0.013초 |
| worker 시작·저장 등 나머지 | 0.158초 | 0.163초 | 0.119초 |

계측 실행의 CLI 내부 분해는 다음과 같습니다. 이 표는 위 CLI 시간 안에 포함됩니다.

| CLI 내부 범주 | 중앙값 | 범위 |
|---|---:|---|
| 시작·실행기 준비 | 0.943초 | Python 시작, import, 계측 준비 포함 |
| 기록 로딩 | 0.014초 | 64회, 중첩 검증 시간 제외 |
| 검증 | 0.017초 | 지정 함수 288회 |
| 원자적 저장 | 0.017초 | 74회, `fsync` 포함 |
| 내부 Git | 0초 | 이 시나리오에서는 호출 없음. Git 전체 비용이 0이라는 뜻이 아님 |
| 기타 CLI 본문 | 0.254초 | 학습·모의 공급자 대기, 잠금, 기타 검사 등 |
| 실행기 종료·계측 장부 잔여 | 0.128초 | 계측 출력 저장과 프로세스 종료 등 |

각 시행의 배타 범주 합은 해당 총시간과 같지만, 범주별 중앙값을 따로 계산하므로 표의 중앙값끼리 더한 값은 총시간 중앙값과 다를 수 있습니다. 계측 실행과 기본 실행의 같은 반복 내 전체 시간 차이는 −0.076~+0.178초, 중앙값 +0.021초였습니다. 이 변동과 실행기 차이를 고려하면 작은 검증·저장 비용을 근거로 제품 최적화를 정당화할 수 없습니다.

모의 서버 종료 대기 개선 후 전체 중앙값은 약 0.607초 짧아졌고, 확인된 큰 변화는 서버 종료 대기였습니다. 나머지 차이까지 해당 설정의 인과 효과로 단정하지 않습니다. 모든 조건에서 같은 평가 결과(기준 MSE 4.940894744681347, 후보 MSE 0.022256767659429855), 역할 14회, 승인 4회, 학습 2회, Git 커밋 4회와 중복 없는 재개를 확인했습니다.

다음 후보는 CLI 시작 구간의 세부 원인과 기록·세션 규모별 비용입니다. 이번 계측 시작 값에는 실행기 준비가 섞여 있으므로 import별 측정이나 새 프로세스 대조로 원인을 좁힌 뒤 개선해야 합니다. 프로세스 사이 캐시나 검사 생략은 도입하지 않았습니다.

후속 [CLI 시작 비용 분해](cli-startup-costs.md)에서 import와 명령 초기화를 구분하고 비계측 대조로 명령 정의 분리의 영향을 확인합니다. 위 수치는 당시 계측 실행기의 이력이며 후속 변경 결과로 덮어쓰지 않습니다.

## 검증과 한계

측정 종료 후 원자료의 MSE를 다시 계산하고 근거 해시, Git에 저장된 파일, 기준 기록 보존, 역할 14회, 승인 4회, 학습 2회, 재개 중 중복 실행 없음을 확인합니다. 산출물 검증 자체는 측정 시간에서 제외합니다. 안전한 관측 경계에서의 재개이며 강제 종료 검증은 [장애 복구 검증](crash-recovery-validation.md)에서 다룹니다.

`mandela` 스킬 관점의 한계는 고정된 시나리오와 검증 요구를 같은 프로젝트에서 설계했다는 점입니다. 공개 원자료·별도 점수 계산·독립 코드 리뷰로 이 시나리오의 동작과 계측을 대조할 수 있지만 실제 사용자의 편익이나 모델 판단 품질을 입증하지 않습니다. 계측 유무와 서버 설정의 실행 순서를 바꾸어 비교하더라도 OS 캐시와 다른 시스템 부하는 완전히 통제하지 못합니다. 작은 반복의 중앙값은 통계적 우월성의 근거가 아닙니다.

실제 API 연결, 네트워크 지연, 토큰 비용, 사용자 작업 시간은 미검증입니다. 이번 결과를 근거로 역할을 합치거나 승인·검토를 제거하지 않습니다.

후속 [기록·세션 규모별 검증](research-scale-costs.md)에서는 기록 수와 완료 세션 수를 분리해 계획·조회·재개의 시간·메모리·출력 변화를 확인합니다.
