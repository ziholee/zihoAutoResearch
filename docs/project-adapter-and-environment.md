# 기존 프로젝트 연결과 실행 환경

갱신: 2026-10-04 · 이전 실행 백엔드 중심 설계를 대체합니다.

## 1. 연결에 필요한 최소 정보

프로젝트를 공통 fit/predict 인터페이스로 바꾸는 대신 기존 작업 방법을 [연구 지침](../templates/program.md)에 기록합니다.

v1에서 명령·환경·지표 등 구조화된 값은 .autoresearch/project.json에 저장하고, program.md에는 해석과 절차를 적습니다. [CLI·파일 계약](cli-and-file-contract.md)이 저장 형식의 기준입니다.

| 정보 | 확인할 내용 |
|---|---|
| 문제 | 대회/프로젝트 목표, 예측 단위·시점, 지표와 방향, 제출 규칙의 출처 |
| 데이터 | 학습·검증·테스트 경로와 버전, 정답, 표본 ID, 시간·그룹 구조, 현재 분할 |
| 코드 | 전처리·학습·검증·추론·제출 파일 생성의 위치와 호출 관계 |
| 환경 | 사용자가 선택한 OS, 기존 런타임/가상환경, 장치, 작업 디렉터리 |
| 명령 | 기존 학습·검증·추론 명령, 입력 설정, 출력 경로, 점수 읽는 위치 |
| 작업 범위 | 수정할 수 있는 파일, 보존할 파일, 실행 예산, 외부 제출 허용 여부 |

LLM은 읽을 수 있는 코드·문서에서 먼저 파악합니다. 없는 내용을 임의로 채우지 않고, 결과를 바꾸는 필수 정보만 질문합니다. 불명확한 선택과 근거는 지침에 남깁니다.

## 2. 기존 환경 사용

Windows·Linux·macOS에서 사용자가 실제 쓰는 환경을 선택합니다. 이 문서는 OS별 실행 관리 시스템을 구현하라는 요구가 아닙니다. 현재 에이전트가 사용할 수 있는 도구로 기존 명령을 실행하고, 확인된 환경만 동작했다고 보고합니다.

장치나 런타임을 조용히 바꾸지 않습니다. 패키지 변경이 필요하면 변경 이유와 범위를 기록하고 기존 환경을 보존하는 방법을 택합니다. 환경 차이가 비교에 영향을 줄 때는 기준을 다시 실행합니다. 경로 표기는 해당 OS의 실제 명령을 따릅니다.

Docker는 초기 설계·구현 범위에서 제외합니다. 가상환경·프로젝트 폴더 분리는 의존성/작업 정리이며 접근 격리 보장이 아닙니다. 현재 도구는 사용자가 맡긴 프로젝트에서 협력적으로 작업하는 흐름을 전제로 합니다.

## 3. 최소한의 연결 코드

기존 학습 명령이 실행되고 결과를 읽을 수 있으면 래퍼를 만들지 않습니다. 점수·분할 ID·실행 설정이 남지 않으면 그 정보만 출력하도록 작은 코드를 추가합니다. 연결을 위해 모델 구조나 전처리 의미를 바꾸지 않습니다.

노트북도 코드와 저장된 출력을 읽어 점검할 수 있습니다. 다만 실행 순서나 현재 코드와 출력의 일치가 불명확하면 실행 사실을 확인 불가로 기록합니다. 반복 실행에 필요한 경우에만 기존 흐름을 보존하는 최소 진입점을 만듭니다.

실험 명령은 실행한 그대로 기록하고 코드 버전·설정·데이터 분할에 연결합니다. 오래된 로그를 새 실행의 결과로 읽지 않도록 실험별 출력 위치를 둡니다. 같은 코드라도 시드·명령이 다르면 별도 실행 기록을 남깁니다.

## 4. 보존과 중단

작업 시작 시 기존 변경 상태를 기록합니다. 기본 경로는 [Git 기반 이력](git-research-history.md)입니다. 코드·설정 커밋과 결과 기록 커밋을 구분하며 기존 사용자 변경은 유지합니다. 비Git/모의 프로젝트의 수동 내용 식별자 기록은 호환 경로로 남기고 Git 검증됨으로 표시하지 않습니다.

실험 실패 시 자신이 만든 변경만 되돌립니다. 원본 데이터·이전 최선 산출물·실험 로그는 보존합니다. 전체 작업 초기화를 운영 규칙으로 삼지 않습니다.

실행 전 한 번의 실행 제한과 남은 연구 예산을 확인합니다. 중단 요청 시 추적 가능한 작업을 종료하고 확인 결과를 기록합니다. 생존 여부를 모르면 종료 완료나 실패로 단정하지 않고 unknown으로 남기며, 확인 전 동일 실험을 다시 실행하지 않습니다. 완전한 자동 복구를 구현하지 않아도 재개자가 상황을 알 수 있어야 합니다.

## 5. 점수와 제출 파일 연결

로컬 점수는 분할·지표·코드/설정·실행에 연결합니다. 제출 점수는 제출 파일의 내용 식별자, 생성한 실험, 대회 제출 ID, 점수 종류(public/private 등), 확인 시각·출처에 연결합니다. 다른 지표나 다른 리더보드의 점수를 한 수치로 섞지 않습니다.

제출 파일 생성과 외부 제출은 별개입니다. 사용자에게 맡겨진 범위에 제출이 포함된 경우에만 실제 제출을 진행하며, 대회 규칙과 잔여 제출 가능 횟수를 확인합니다. 사용자가 직접 제출한 점수도 출처를 표시해 기록할 수 있습니다. 제출하지 않은 후보는 점수를 빈 상태로 두며 추정하지 않습니다.

주최측 데이터·평가 방식이 이미 있으면 그것을 활용합니다. 새 평가 서버나 범용 데이터 어댑터를 만드는 작업은 필요하지 않습니다.
