# 역할별 요청 맥락 측정과 중복 제거

개발 구현의 `research metrics`는 역할별 준비 메시지를 지침·소스·기록·누적 응답·기타·JSON 구조로 나누어 UTF-8 바이트와 관측 수를 제공합니다. 실제 네트워크 전송량·토큰·요금 또는 판단 품질 측정이 아닙니다. 공개 v0.3.0에는 이 개발 기능이 없습니다.

## 측정 계약

`input_components_bytes`는 trace에서는 정수 분해값이며, metrics의 전체·역할별 집계에서는 각 항목의 `value`와 `observations`입니다.

| 항목 | 포함 범위 |
|---|---|
| `instructions` | system 메시지 전체: 공통 경계·역할 지침·출력 형식·참조 설명 |
| `sources` | user JSON의 `sources` 필드 |
| `records` | `records`, `observation`, `comparison`, `prior_lessons`, `next_context`, `revision_context` |
| `outputs` | 이번 세션의 누적 역할 응답 `outputs` |
| `other` | 목표·프로젝트·실행 조건·식별자 등 나머지 최상위 필드 |
| `framing` | 최상위 중괄호와 필드 사이 쉼표 |

각 JSON 필드는 키·콜론·직렬화된 값을 포함합니다. 따라서 여섯 항목의 합은 `input_message_bytes`와 정확히 같습니다. 중첩 객체의 문법은 해당 필드에 포함됩니다. 메시지 envelope·HTTP 헤더는 제외합니다. 정규 compact JSON과 system/user 두 메시지 형식만 분해하며, 지원하지 않는 형식을 재직렬화해서 실제 관측으로 표시하지 않습니다.

기존 측정 버전 1에 선택 필드를 추가했습니다. 과거 trace나 준비 실패에 분해값이 없으면 `null`, 관측 수 0으로 남습니다. 잘못된 숫자·불완전한 분해·전체 바이트와 합이 다른 분해는 집계하지 않습니다. 원문을 측정 필드에 추가 저장하지 않습니다.

## 적용한 범위

1. 역할 지침 버전 2에서는 `changes` 출력 형식의 상세 설명을 **구현·검토**에 유지합니다. 이 출력을 생성하지 않는 분석·평가·계획·해석·기억에서는 제외합니다. 실제 응답 스키마와 검증기, 공통 권한·근거 제한은 유지합니다.
2. **해석·기억 요청에서만**, 구현 제안의 파일 본문이 같은 요청의 현재 소스와 바이트 단위로 일치하고 SHA-256도 일치하면 `content` 대신 `content_ref: {"path": "...", "sha256": "..."}`를 보낼 수 있습니다. `context_encoding: "source_refs_v1"`와 system 설명을 함께 보냅니다. 참조는 같은 요청의 `sources[path].content`를 뜻하며 도구 호출이나 외부 파일 읽기가 필요하지 않습니다.
3. 참조와 설명을 포함한 전체 메시지가 더 작을 때만 참조화를 적용합니다. 짧은 파일·누락·불일치·잘못된 해시는 원문을 유지합니다.

실행 전 검토에는 원본 소스와 제안한 전체 파일이 그대로 전달됩니다. 저장된 제안·diff·승인 토큰의 입력은 바꾸지 않고 전송용 복사본만 변환합니다. 변경 승인·판단 확정·실행 횟수·unknown 복구 절차는 유지합니다. 기록 요약과 실행 관측은 같은 실험을 가리켜도 담는 정보가 달라 일괄 제거하지 않습니다.

## 재현과 관측 결과 — 2026-10-20

개발 소스 설치 후 다음 명령을 실행합니다. 출력 폴더는 새 경로여야 합니다.

```sh
python -m pip install .
python scripts/benchmark_request_context.py --output ./request-context-results
```

기존 합성 ML 예제를 모의 HTTP 공급자로 실행합니다. baseline·candidate 각 7역할, 실제 학습 2회, 승인 경계와 새 프로세스 재개를 확인합니다. 출력의 `workflow/`에는 로컬 실행 근거가 남고, `summary.json`에는 원문·로컬 경로 없이 역할별 숫자와 코드 해시가 저장됩니다.

전후 비교의 기준은 dev `25edfae`의 요청 구성에 분해 측정만 추가한 실행입니다. 이후 동일한 예제·데이터·결정적 응답으로 변경된 요청 구성을 실행했습니다. 각 실행의 코드 해시와 모든 역할 관측은 [공개 원자료](benchmarks/request-context-results.json)에 있습니다. 현재 명령은 변경 후 구성을 재현합니다. 기준 실행에는 아직 참조화와 역할별 지침 축소가 없습니다.

| 14회 합계 | 변경 전 | 변경 후 |
|---|---:|---:|
| 지침 | 27,888 | 25,326 |
| 소스 | 12,886 | 12,886 |
| 기록 | 54,364 | 54,364 |
| 누적 응답 | 7,230 | 6,824 |
| 기타 | 18,502 | 18,572 |
| JSON 구조 | 308 | 310 |
| **전체 바이트** | **121,178** | **118,282** |

전체는 **2,896바이트(약 2.39%)** 감소했습니다. 지침에서 10회 × 286바이트를 줄였고, 작은 후보 소스의 참조화는 설명 등을 포함하면 해석·기억에서 각각 18바이트를 추가로 줄였습니다. 참조화의 효과가 이 작은 예제에서는 크지 않다는 점도 함께 기록합니다. 구현·검토 요청 크기, 소스·기록 바이트는 동일했습니다.

양쪽 모두 실제 실행 2회·역할 호출 14회이며 재개에서 재실행이 없었습니다. 기준 MSE 4.940894744681347, 후보 MSE 0.022256767659429855로 같았습니다. 이는 합성 데이터와 고정 모의 응답의 동작 확인이며 LLM 연구 능력의 증거가 아닙니다.

## 검증과 한계

다국어·따옴표·개행을 포함한 분해 합과 실제 바이트, 과거 측정의 미확인 처리, 참조를 원문으로 복원한 동등성, 불일치·작은 소스의 원문 유지, 실행 전 검토 근거, 승인 전 실행 금지·잘못된 토큰 거부·중복 실행 금지를 회귀 검사합니다. 설치한 wheel과 sdist의 예제로도 14회 측정과 재개를 확인합니다.

`mandela` 관점에서 모의 공급자가 정해진 답을 반환하므로 이 결과로 실제 모델의 참조 이해나 판단 품질을 검증했다고 할 수 없습니다. 바이트 감소는 직렬화된 내용의 직접 측정과 독립 복원 검사로 확인하고, 실제 API·Codex 인증·추론·비용·품질 검증은 보류합니다. 역할 호출을 생략하지 않았으며, 로컬 실행 속도 개선도 주장하지 않습니다.
