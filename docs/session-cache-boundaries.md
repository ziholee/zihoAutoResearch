# 큰 완료 세션과 캐시 경계

2026-10-21 · 모의 공급자와 합성 이력 기준입니다. 실제 API 지연·요금·모델 판단 품질은 검증하지 않습니다.

## 목적과 조건

[완료 세션 조회 개선](completed-session-costs.md)의 작은 이력 1,000개 측정을 확장합니다. 기록은 100개로 고정하고 다음 조건을 독립적으로 측정합니다.

- 항목 경계: 2,047·2,048·2,049개. 전체 입력은 8MiB보다 작습니다.
- 바이트 경계: 128개 이력의 정규화 UTF-8 입력 합계를 정확히 8MiB−1·8MiB·8MiB+1로 맞춥니다.
- 큰 일반 응답: 16개 이력, 각각 1MiB. 기억을 제외한 여섯 역할의 `uncertainties`에 본문을 분산합니다.
- 큰 기억: 2,500개 이력, 각 `memory.lesson` 16,000자. 최신 5개를 요청 맥락에 넣습니다.

성능 측정 fixture의 모든 역할 출력은 측정 대상 소스의 `validate_response`를 통과합니다. 역할별 256,000바이트·문자열 20,000자와 세션 파일 2,000,000바이트 제한을 지킵니다. 이는 역할 문법을 만족하는 합성 이력이며 실제 학습·모델의 유용한 판단을 뜻하지 않습니다. 캐시 단위 검사의 단순 패딩 문서는 별도로 캐시 경계만 검사합니다.

2,048개·8MiB는 캐시에 보관하는 **입력의 범위**입니다. 객체·현재 읽는 파일·응답·Python 실행 환경을 포함한 프로세스 RSS 상한이 아닙니다. 한도 밖 파일도 모두 읽고 검증하며 필요한 경우 다시 파싱합니다.

## 확인한 병목과 최소 변경

큰 기억을 가진 이력에서는 캐시 밖의 기억까지 모두 `lessons` 목록에 쌓은 뒤 정렬해 마지막 5개만 반환했습니다. 사전 진단에서 16,000자 기억 2,500개는 약 43MB의 최고 추적 할당을 보였습니다. 후보를 최근 5개로 제한한 임시 구현에서는 약 10MB였습니다. 이 단일 프로파일 진단은 정식 성능 개선율 계산에 사용하지 않습니다.

이제 각 기억을 읽은 뒤 최대 6개 후보를 안정 정렬해 최근 5개만 유지합니다. 파일명 순서로 순회하므로 동률의 기존 순서를 유지합니다. 캐시 항목·바이트 한도, 매 역할의 파일 열거·경로 안전 검사·전체 읽기·내용 해시·엄격한 파싱은 바꾸지 않습니다. 변경·추가·삭제·잘못된 JSON을 기존대로 반영하거나 거부합니다. 반환 기억은 복사하며 승인·호출 예산·중단·재개 절차는 그대로입니다.

경계에서 발생하는 정상적인 캐시 미스나 경로 안전 검사를 없애지 않습니다. 속도보다 불필요한 큰 기억의 동시 보관을 줄이는 변경입니다.

## 재현과 측정 범위

```sh
python3.11 scripts/benchmark_session_boundaries.py --source /path/to/before --output /tmp/boundary-before --repeats 3 --label before
python3.11 scripts/benchmark_session_boundaries.py --source . --output /tmp/boundary-after --repeats 3 --label after --compare /tmp/boundary-before/summary.json
```

변경 전은 `0bfc52a`입니다. 각 조건·명령은 준비 실행 1회 후 3회 측정합니다. 변경 전 전체 실행 후 변경 후 전체 실행 순서이며 정식 측정 동안 다른 테스트·빌드는 병행하지 않습니다. 동일 측정 코드·Python·OS·입력 바이트·소스 해시를 기록하고, 전후 CLI 의미·역할·기억·예산·승인 토큰·원문 보존을 대조합니다.

시간은 Python 시작·CLI·출력·저장 세션과 승인 토큰 확인·메타데이터 저장·출력 수집·종료를 포함합니다. 입력 생성·복사·역할 문법 검증·재개 준비·부모 검증은 제외합니다. RSS는 측정 자식 전체의 최고치입니다. OS 파일 캐시가 따뜻한 조건이며 한도 경계의 작은 차이를 통계적 우월성으로 해석하지 않습니다.

계획은 5개 역할 뒤 승인 대기까지, 조회는 승인 대기 상태 확인입니다. 재개는 2개 성공 응답을 저장한 뒤 세 번째 모의 요청에서 중단하고, 새 프로세스가 남은 3개 역할을 수행합니다. 실제 OS 강제 종료·학습·복구 성능은 이 측정에 포함되지 않으며 기존 기능 검사에서 별도로 검증합니다.

## 검증

실제 2,048개·8MiB 경계에서 최신 기억 선택·캐시 한도·재파싱 횟수와 캐시 밖 최신 파일의 동일 크기·동일 mtime 수정·잘못된 JSON·삭제를 검사합니다. 기억 객체의 수명을 추적하는 회귀는 기존 구현에서 동시에 50개를 유지해 실패하고, 변경 후 최근 후보와 처리 중 객체만 유지해 통과합니다. 기존 동률·파일 추가·상태 수정·심볼릭 링크·중단과 성공 응답 보존 검사를 유지합니다.

측정 도구 자체는 정확한 바이트·역할 제한·큰 응답과 기억의 실제 CLI 계획/조회/재개·잘못된 기억 순서의 거부를 검사합니다. 원자료는 수치와 해시만 공개하고 합성 원문·명령 출력은 측정 폴더의 `private/`에 둡니다.
