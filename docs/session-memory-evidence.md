# 세션 기억의 근거와 보류

상태: 개발 브랜치 구현 · 미배포. 실제 API 추론 품질과 실험 개선 효과는 검증하지 않았습니다.

## 목적

세션의 기억은 LLM이 작성한 제안입니다. 사용자 `keep` 결정, 검토 역할의 `pass`, 측정 점수의 개선만으로 원인이나 다른 실험에서의 효과를 입증하지 않습니다. 모델의 설명과 CLI가 원본에서 확인할 수 있는 관찰·참조를 분리합니다.

[Harness² 논문](https://arxiv.org/html/2610.14224v1)의 실행 비교에 근거한 교훈과 근거 부족 시 보류 원칙을 참고했습니다. 해당 프레임워크의 자동 하네스 편집·반복 탐색·성능 수치를 가져온 것은 아닙니다. zar의 단일 기준/후보 비교에는 반복 대조와 효과 분리가 없으므로 재사용 가능한 인과적 교훈으로 자동 승격하지 않습니다.

## 제안과 CLI 판정

모델의 `lesson`, `limitation`, `next_action`과 공통 `summary`, `evidence`, `uncertainties`는 원래 제안으로 보존합니다. 새 기억 계약에서는 `contrast`로 주장한 효과, 적용 상황, 전달받은 근거 핸들을 구조화할 수 있습니다. `contrast`를 생략한 기존 응답도 허용하지만 근거 부족으로 보류합니다. 존재하지 않는 근거와 잘못된 형식은 정상적인 근거 부족과 달리 응답 오류입니다. 실패한 호출도 기존 호출 예산을 소비하며 자동 재시도하지 않습니다.

CLI는 실제 실험·기준 실험과 비교 결과에서 관찰 및 출처를 생성합니다. 모델이 입력한 조건이나 해시를 사실로 채택하지 않습니다. 지표 차이의 방향은 원인 설명과 별개입니다. 비교 불가, 원본 누락/변경/정정, 불명확한 실행, 여러 효과의 혼재는 보류 사유입니다. 단일 비교에서 점수가 좋아져도 `hold`이며, 현재 구현에는 효과를 검증 완료로 자동 승격하는 경로가 없습니다.

보류는 기억 처리를 실패시킨다는 뜻이 아닙니다. 유효한 응답은 제안과 한계를 남기고 세션을 `complete`로 마칠 수 있습니다. 보류된 설명을 다음 실행의 근거나 승인으로 간주하지 않습니다. 다음 작업에서 필요한 대조나 관찰을 마련할 때 참고하는 자료입니다.

## 필드와 근거 범위

새 세션에는 `memory_contract_version: 1`이 저장됩니다. 기억 호출의 `memory_evidence`는 원본 기록의 ID·revision·정규화 JSON SHA-256, 선언된 비교/환경/run_context, 점수 필드(`/execution/score`)를 가리키는 핸들, 비교 결과를 제공합니다. `contrast`는 정확히 다음 필드를 가집니다.

| 필드 | 의미 |
|---|---|
| effect | `helped`, `hurt`, `no_observed_effect`, `confounded`, `insufficient_evidence` 중 모델의 주장 |
| applicability | 적용 상황 설명, 1~2,000자 |
| evidence | 전달된 핸들 중 최대 20개, 중복 불가. 실제 받은 문자열을 그대로 사용 |

공통 `evidence`의 기존 출처 이름 검사와 `contrast.evidence`의 점수 핸들 검사는 별개입니다. 두 실험의 핸들을 모두 인용하지 않으면 불완전한 비교 근거로 보류합니다.

세션의 `memory_assessment`와 최근 기억의 `assessment`는 CLI 판정입니다. `claim_effect`는 모델의 주장, `observed_effect`는 기록된 점수 차이의 방향이며 유효한 비교가 없으면 null입니다. 최소 개선량 충족 여부는 `comparison.meets_min_delta`를 따로 확인합니다. 미세한 양의 차이라는 사실만으로 채택이나 통계적 유의성을 뜻하지 않습니다. `reasons`에 누락·불일치·단일 비교·분리 대조 미확인 등의 한계를 보존합니다.

`evidence_files_checked: false`는 이 판정이 로그·지표 파일을 다시 열어 진실성을 검증한 결과가 아니라는 뜻입니다. 여기서 확인하는 해시는 저장된 실험 레코드의 식별자입니다. 기존 실행/판단/next의 근거 검사 절차를 대체하지 않습니다.

## 재사용과 호환성

새 세션은 [관련성 기반 선택](session-memory-relevance.md)으로 완료 기억을 최대 5개 고릅니다. 선택 정책 버전이 없는 기존 세션은 최근 완료 기억 5개 방식으로 재개합니다. 원본 제안을 덮어쓰지 않고, 재조회 시 현재 기록과 출처를 대조해 상태를 함께 전달합니다. 오래된 판정을 캐시만 믿고 유효한 근거로 재사용하지 않습니다. `research next`도 새 세션의 전송·승인을 유지하며, 부모 기억을 실행 권한으로 승격하지 않습니다.

기존 완료·중단 세션은 자동 마이그레이션하지 않습니다. 구버전 기억은 미평가로 구분하고 기존 재개 경로를 유지합니다. 새 세션의 기억 계약 버전은 고정하며 승인 토큰에 포함합니다. 추가 LLM 호출, 자동 실험, 자동 스킬 변경은 없습니다.

수동 [실패 기억](failure-memory.md)은 별도 불변 기록입니다. 세션 제안을 `memory add`로 자동 등록하거나 기존 기억을 정정하지 않습니다. 수동 기억에 이미 있는 조건·근거·정정 개념을 활용하되 관찰과 인과 설명의 구분을 유지합니다.

## 검증 범위

모의 공급자와 합성 지표로 정상 비교, 근거 부족, 혼재, 조작된 참조, 구버전 재개와 승인·호출 예산 경계를 검사합니다. 모의 응답을 잘 거르는 것은 실제 모델의 교훈 생성 품질이나 비용 절감을 입증하지 않습니다. 실제 API 연결은 별도 검증으로 남깁니다.
