# 공개 v0.1.0 사용 경로 검증과 v0.1.1 수정 대상

검증일: 2026-10-11 KST. [공개 v0.1.0](https://github.com/ziholee/zihoAutoResearch/releases/tag/v0.1.0)의 wheel·소스 배포본·SHA256SUMS를 인증 없이 새 임시 폴더에 다운로드하고 해시를 확인했습니다. 새 가상환경에 wheel을 설치했습니다.

## 방법과 결과

독립 검증 담당은 배포본 README·스킬·레시피·문서만 읽고 새로운 합성 수요 예측 프로젝트를 구성했습니다. 구현 소스와 저장소 테스트를 참고하지 않았으며, 기존 mock-cycle을 호출하지 않고 공개 CLI로 자체 시나리오를 작성했습니다. 정확한 숫자 직렬화에는 문서에 소개된 codec만 사용했습니다.

- full 기준 실험의 합성 점수 2.7을 기록하고 keep과 선택을 별도로 설정.
- 두 번째 실험을 planned→running→unknown으로 기록한 뒤 준비 프로세스 종료.
- 별도 재개 프로세스에서 context/status로 같은 ID를 찾음. 새 근거 없는 unknown 해소는 거부되고 원본이 보존됨.
- 새 확인 근거를 추가해 같은 ID를 성공 상태로 해소. 기존 근거 순서와 기준 원본 유지, 예산 사용은 2.
- full/full의 합성 점수 2.5는 숫자상 정확한 개선 0.2. 근거 파일 변조 후 evidence read는 발췌 없이 거부하고 check/compare는 경고. 에이전트는 숫자만으로 채택하지 않고 hold.
- 별도 full/proxy 사례는 비교 불가·null 개선값으로 hold. 추가 실험 생성은 소진된 예산으로 거부.
- 보고서와 조회가 원본 JSON을 바꾸지 않으며 최종 선택은 기준 실험, 미완료 목록은 비어 있음.

**검증한 범위에서 런타임 결함은 발견하지 않았습니다.** unknown이 있는 동안 CLI가 모든 신규 실험을 일괄 금지한다는 뜻은 아닙니다. 재개 절차는 에이전트가 지키고, 횟수 예산은 CLI가 검사합니다. 실제 ML 품질·실패 방지율·프로세스 중단 복구를 입증한 검증도 아닙니다.

## 재현된 문서 개선 대상

| 항목 | v0.1.0 관측 | v0.1.1 처리 |
|---|---|---|
| 초안 폴더 생성 누락 | 레시피가 `.autoresearch/drafts/`를 안내하지만 init은 만들지 않음. 해당 경로에 직접 초안 작성 시 FileNotFoundError | 선택 폴더를 먼저 생성하거나 외부 초안 경로를 쓰도록 명시. init의 기존 동작 유지 |
| 근거 조회 종류 설명 불일치 | 레시피 일반 설명은 3종만 열거하지만 공개 help는 memory/candidate를 포함한 5종 지원 | 지원 종류와 해당 포인터 예시 수정 |
| 재개 절차 분산 | 필요한 규칙은 존재하지만 설치·설정·unknown 해소·경고 해석을 여러 절에서 조합해야 함 | [처음 사용과 재개 안내](first-run-and-resume.md) 및 두 프로세스 모의 사례 제공 |

첫 두 항목은 공개 문서/CLI로 재현한 안내 문제이고, 세 번째는 사용 경로를 따라가며 확인한 문서 구성 개선입니다. 안전 검사 실패를 제품 결함으로 재분류하지 않았습니다. 스키마·실행 정책·자동 채택 규칙은 바꾸지 않습니다.

자체 시나리오는 `examples/mock-resume.py`로 정리해 패키지 검증에 포함합니다. 최초 검증은 로컬 격리 환경의 한 에이전트 시도이며 다수 사용자 연구가 아닙니다. 변경 버전의 CI 결과는 해당 PR과 CI을 기준으로 확인합니다.
