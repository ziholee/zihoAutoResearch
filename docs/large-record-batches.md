# 큰 기록·크기 편차가 있는 배치 검증

2026-10-22 · 모의 공급자·합성 기록 기준입니다. 실제 API나 학습 성능은 검증하지 않습니다.

## 목적과 결정

기록 해시는 64개 문서씩 처리하지만 바이트 상한은 없습니다. 큰 문서가 섞인 63·64·65개 경계와 10,000개 혼합 조건의 시간·메모리를 확인합니다. 사전 진단에서 배치를 32·16개로 줄이면 임시 할당은 줄지만 10,000개 기록 처리 시간이 늘었습니다. 분포에 따른 비용 교환이므로 전역 배치 축소를 채택하지 않았습니다.

이번 변경은 측정 도구·회귀 검사·문서에 한정하며 `zar/` 실행 코드는 변경하지 않습니다. 정식 측정의 before/after 라벨은 **같은 실행 코드의 두 동결 사본 A/B**입니다. 관측 차이는 개선 효과가 아니라 실행 변동입니다.

## 입력 조건

- 경계 조건: 기록 63·64·65개, 완료 세션 0개.
- 혼합 조건: 기록 10,000개, 완료 세션 2,500개, 기억 본문 16,000자.
- 모든 조건에서 기록 index 0·31·62의 `hypothesis`만 각각 `x`·`한`·`😀` 262,144자로 바꿉니다. 큰 문서 수와 위치는 동일합니다.
- 큰 본문 UTF-8은 각각 262,144·786,432·1,048,576bytes입니다. **문자 수와 바이트 수는 다릅니다.** 각 기록 파일 크기·전체 입력 크기를 원시 보고서에 제공합니다.

세 큰 기록은 모두 첫 64개 배치 안에 있습니다. 이 구성은 경계를 넘을 때 큰 문서를 추가하는 효과와 혼동하지 않게 하지만, 큰 기록이 다른 배치로 이동하는 모든 위치를 대표하지 않습니다. 단일 문서 크기 한계나 임의 분포의 메모리 상한을 보장하지 않습니다. 모든 fixture는 기존 기록·역할 검증 경로를 통과합니다.

## 재현과 범위

```sh
# before에는 기준 커밋 4857c05의 별도 사본을 사용합니다.
python3.11 scripts/benchmark_large_records.py --before /tmp/before --after . --output /tmp/large-record-batches --repeats 3
python3.11 scripts/verify_mixed_research.py --source . --output /tmp/large-record-verification --large-characters 262144
```

각 조건에서 기록 해시 control·별도 allocation, CLI 계획·조회·재개를 측정합니다. 작업별 준비 1쌍 뒤 A→B, B→A, A→B의 3쌍을 실행합니다. 모든 표본은 새 프로세스이고 CLI는 공통 fixture를 독립 복사합니다. 기존 교차 측정·기록 해시·세션 경계 worker와 검증기를 재사용합니다. 정식 측정 중 다른 테스트·빌드를 병행하지 않습니다.

단독 해시 시간은 검증된 기록 로딩 뒤 실제 함수를 호출하는 시간입니다. 할당 추적은 별도 실행으로 입력 스냅샷을 제외합니다. 측정이 끝난 뒤 별도 호출에서 SHA256 입력 바이트를 private 파일로 기록하여 직접 대조합니다. 단독 추적 할당과 프로세스 RSS는 다른 지표입니다.

CLI 시간은 시작·CLI·출력·저장 토큰 검사·메타데이터·종료를 포함합니다. 준비·복사·부모 검증은 제외합니다. 재개는 두 성공 역할을 보존하고 모의 요청을 중단한 뒤 새 프로세스가 세 역할을 수행하는 조건이며, OS 강제 종료·실제 학습 성능은 범위 밖입니다. 기존 unknown·복구 회귀는 유지합니다.

소스·도구·입력 해시와 바이트·CLI 의미·최근 기억·호출 예산·승인·원문 보존을 확인합니다. 공개 JSON에는 수치·해시만 남기며 원문은 `private/`에 둡니다.

## 큰 기록 변경 감지 검증

`verify_mixed_research.py --large-characters`는 같은 고정 위치의 큰 기록 fixture를 적용합니다. 10,000개·큰 기억 2,500개 조건에서 기록 수정·추가·삭제·정정, 역할 사이 변경, 이력 갱신, 별도 프로세스 재개, 정상 승인과 오래된 입력의 승인 거부를 검사합니다. 크기·mtime을 유지한 수정도 포함합니다. 변조 실행을 성능 표본에 넣지 않습니다.
