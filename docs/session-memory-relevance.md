# 세션 기억의 관련성 기반 선택

상태: 개발 브랜치 구현 · 미배포. 모의 공급자·합성 이력으로 검증하며 실제 API와 기억 재사용의 ML 개선 효과는 검증하지 않습니다.

## 선택 원칙

새 세션은 전체 완료 이력을 살펴 현재 실험의 선언 조건과 관련된 기억을 최대 5개 전달합니다. 최신 5개를 먼저 잘라 비교하지 않으므로 오래된 관련 기억도 선택할 수 있습니다. 모델의 자유문장 유사도나 임의 가중치, 추가 LLM 호출을 사용하지 않습니다.

1. 비교 조건·환경·실행 범위·예산 식별자가 알려져 있고 일치하는 `matched` 기억을 먼저 고릅니다.
2. 조건이나 과거 출처가 충분하지 않은 `unknown` 기억은 부족한 자리를 채우되 미확인 사유를 함께 전달합니다.
3. 알려진 조건 불일치와 변경·정정된 원본은 제외합니다. 적합한 후보가 없으면 5개를 채우려고 부적합한 기억을 넣지 않습니다.
4. 같은 분류에서는 생성 시각이 최신인 순서, 동률이면 세션 ID 내림차순으로 고릅니다.

비교 조건은 comparison 전체(식별자·데이터·분할·지표·방향·평가 방식·최소 개선량), 선언 환경, run_context의 scope와 budget_ref를 대조합니다. seed·코드·설정 차이는 실험 탐색에서 생길 수 있으므로 단독 제외 기준으로 삼지 않습니다. 이 차이를 무시하고 효과가 전이된다고 판정하는 것도 아닙니다. 자유문장 `applicability`를 기계적으로 검증된 조건으로 취급하지 않습니다.

관련성은 효과의 확실성이 아닙니다. 선택된 기억의 `hold` 또는 `unassessed`를 그대로 유지하며, 조건이 일치해도 검증된 교훈이나 실행 권한으로 승격하지 않습니다. [기억 근거 판정](session-memory-evidence.md)과 별도입니다.

## 전달되는 선택 설명

각 `prior_lessons` 항목은 원래 제안·`assessment`에 `relevance`, `condition_matches`, `selection_reasons`, `differences`를 함께 담습니다. `differences`의 seed와 코드·설정 참조는 정보가 있을 때만 표시하며 제외 조건이 아닙니다. 조건 비교는 저장된 조건 사본을 그대로 믿지 않고 해시가 일치하는 실제 원본 기록으로 수행합니다.

맥락의 `memory_selection`은 정책 버전·개수 한도와 집계를 제공합니다. `eligible`은 완료 상태이고 기억이 있는 후보 수(제외 전), `matched`/`unknown`은 조건 분류 수, `mismatch`/`source_changed`는 제외 수, `limit`은 최대 5개 한도 때문에 전달하지 않은 후보 수입니다. 잘못된 대비 근거 핸들은 순위를 정하기 전에 제외하므로 다음 정상 후보가 선택됩니다.

구버전 기억은 생성 당시 출처를 입증할 정보가 없으면 현재 실험 ID가 존재하더라도 `unknown`으로만 분류합니다. 참조 ID가 명시되어 있는데 원본이 삭제·정정된 경우는 제외합니다. 참조 자체가 없는 과거 기억은 미확인 fallback이며 효과 근거로 취급하지 않습니다.

## 호환성과 변경 감지

새 세션은 `memory_selection_version: 1`로 선택 정책을 고정합니다. 이 값은 승인 토큰에 포함됩니다. 값이 없는 기존 세션은 기존 최근 5개 선택·출력 순서로 재개하며, 저장된 세션을 자동 변환하지 않습니다. 기억 응답의 `memory_contract_version`과 선택 정책 버전은 별개입니다.

이력은 각 역할 호출 때 다시 읽고 내용 해시로 변화를 확인합니다. 파일 크기와 mtime만 같다고 캐시를 신뢰하지 않습니다. 현재 기록 스냅샷 안에서 원본 해시 계산을 공유하되 다음 호출까지 유효하다고 가정하지 않습니다. 원본 제안과 기록은 수정하지 않습니다.

개수 상한과 기존 2,048항목·8MiB 이력 캐시 한도, 역할 맥락·next의 바이트 제한을 유지합니다. 많은 세션이 같은 실험을 참조해도 동일 스냅샷에서 반복되는 원본 해시 계산을 공유합니다. 현재 선택한 실험과 `research next`가 명시적으로 연결한 부모는 자동 회상과 별개이며, 이 연결이 새로운 승인을 대체하지 않습니다.

## 검증

오래된 조건 일치 기억, 최신 불일치, 정보 부족, 동률, 원본 변경·삭제·정정, 같은 크기/mtime의 이력 수정, 구버전 재개와 토큰 변경을 검사합니다. 추가 모델 호출 없이 선택 정보가 실제 모의 HTTP 요청에 전달되는지도 확인합니다. 규모 검사는 선택기 비용과 전체 CLI 계획·조회·재개 비용을 구분합니다. 측정 결과만으로 실제 모델의 판단 품질이나 비용 절감을 주장하지 않습니다.

### 선택기 규모 측정 (2026-10-23)

[원시 결과](benchmarks/session-memory-relevance.json)는 선택기만 따로 측정한 13개 조건입니다. 합성 기록은 선택에 필요한 필드로 구성했으며 전체 CLI 스키마 검증·기록 로딩·Python 시작·모델 호출 비용을 포함하지 않습니다. 준비 1회 후 cold/warm 순서로 3쌍을 측정했습니다. cold/warm은 파싱 캐시의 비어 있음/재사용을 뜻하며 OS 파일 캐시를 통제한 실험은 아닙니다. 할당 메모리는 시간 측정과 분리한 tracemalloc peak이고 프로세스 RSS가 아닙니다.

모든 조건에서 수동 지정한 기대 ID·분류 집계·hold와 캐시 유무별 결과가 일치했습니다. 공통 원본을 참조하는 이 분포에서 원본 식별자 계산은 호출당 3–4회, 기록 전체 순회는 1회였습니다. 2,500개 조건 일치 분포에서도 변경된 원본 1개를 제외한 뒤 최신 5개를 선택했습니다. 이는 공유 원본의 중복 작업이 제한됨을 확인한 결과이며, 모든 기억이 서로 다른 기록을 참조할 때도 해시 횟수가 일정하다는 뜻은 아닙니다.

이전 버전과의 성능 비교가 아니며, 관련성 선택이 속도나 실제 모델의 실험 품질을 개선했다는 근거로 사용하지 않습니다.

### 실제 CLI 혼합 조건

Python 3.11.17 / macOS arm64에서 [전체 CLI 원시 결과](benchmarks/session-memory-relevance-cli.json)를 측정했습니다. 두 arm 모두 같은 최종 소스이며 `before`/`after`라는 도구 필드명은 버전 개선 비교를 뜻하지 않습니다. 조건별 준비 1쌍·측정 1쌍으로 총 12개 측정 표본을 확인한 기능·자원 사용 스모크입니다. 작은 조건은 기록 100개·완료 세션 0개, 혼합 조건은 기록 10,000개·완료 세션 2,500개·기억 본문 16,000자입니다.

각 arm의 의미 결과 해시와 기대 기억 순서가 일치했습니다. 해당 전체 CLI 이력은 구버전 출처가 없는 `unknown` fallback이며, 모든 후보가 조건 일치하는 스트레스는 위 선택기 검사로 별도 확인했습니다. 요청 합계는 역할 호출 전체의 합이며 단일 맥락 한도와 다릅니다. 같은 코드에서도 계획 시간이 변동하므로 이 표로 속도 향상이나 회귀를 판정하지 않습니다.

### 회귀·배포 파일 검증

전체 단위·통합 테스트 526개와 모의 HTTP의 새 CLI 프로세스 검증이 통과했습니다. 설치 wheel/sdist의 합성 실험·복구·스킬 추출 검사도 통과했습니다. [큰 기록 혼합 검증](benchmarks/session-memory-relevance-mixed.json)은 기록 10,000개 중 3개에 ASCII·한글·이모지 본문을 각각 262,144자 넣고 완료 세션 2,500개를 함께 사용했습니다. 기록 변경·추가·삭제·정정, 역할 사이 변경, 이력 변경, 새 프로세스 재개, 승인 필요, 오래된 승인 거부의 9개 시나리오가 통과했습니다. 실제 API 연결과 실제 모델의 기억 활용 효과는 후속 검증입니다.
