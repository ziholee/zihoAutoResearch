# LLM을 연결하는 실험 CLI 설계

갱신: 2026-10-15 · 상태: API 연구 세션 개발 구현, 미배포

실제 명령과 재개 절차는 [API 연구 세션 사용법](research-api.md)을 따릅니다. 아래 장기 목표와 현재 구현을 구분합니다. 실제 클라우드 API 검증은 사용자 요청에 따라 후속으로 남겼으며 모의 공급자 검증을 실제 연결 성공으로 표시하지 않습니다.

## 현재 구현 범위

- `research setup`의 질문에 답하면 기존 프로젝트 폴더에 설정과 세션을 저장하고, 별도 전송 동의 후 첫 계획을 만듭니다. JSON 수동 편집 없이 진행하며 기존 설정도 기본값으로 사용합니다. 비대화형 자동화는 기존 명시적 설정·시작 명령을 사용합니다.
- 실행 전 `research revise`로 누락 질문·수정 요청을 입력하고 기존 설정을 검토하여 연결된 새 계획을 만듭니다. 저장 시 이전 세션을 비활성화하고 새 전송 동의와 승인을 요구합니다. `status`의 `next_actions`는 상태별 다음 명령과 확인 조건을 안내합니다.
- OpenAI 호환 Chat Completions API에 분석·평가·설계·구현·변경 검토·해석·기억 지침을 각각 주입합니다. 모델에는 실행 도구를 제공하지 않습니다.
- 사용자 전송 동의 후 제안을 만들고, 구체적인 diff·설정 명령의 승인 뒤 한 번 실행합니다. 결과는 실제 로그와 명시한 지표 파일에서 수집합니다.
- `baseline` 모드는 현재 원본 코드에 모델 변경을 적용하지 않고 승인된 실행으로 기준을 측정합니다. `candidate`는 비교 가능한 선택된 유효 keep 실험을 요구합니다. 선택이 없으면 기본 모드는 baseline, 있으면 candidate입니다.
- 완료된 세션의 `research next`는 설정·연결·제한된 관측·확정 판단·기억 맥락을 새 세션에 이어 줍니다. 새 지표 경로, 저장·전송 동의와 새 승인이 필요하며 이전 완료 세션을 변경하지 않습니다.
- 해석 제안 → 사용자 판단 확정 → 기억 제안 저장 순서로 완료합니다. 다음 실험 자동 반복은 없습니다. 기억은 최근 완료 세션 5개의 제안으로 전달하며 canonical 실패 기억 등록과 구분합니다.
- 호출·파일 적용·판단 저장 도중 종료는 recover, 실행 불명 상태는 실제 근거 갱신 뒤 reconcile로 처리합니다.
- 설치된 Codex·Claude Code 실행 어댑터, 실제 공급자 호환성, Windows 실행과 실제 ML 효용 비교는 완료하지 않았습니다.

## 목표와 결정

사용자가 터미널에서 모델을 연결하고 자연어로 목표를 전달하면, 프로젝트 파악부터 승인된 실험 실행·기록·재개까지 이어갈 수 있게 합니다. 사용자가 기록용 JSON을 직접 작성하는 것을 기본 흐름으로 요구하지 않습니다.

- 사용자 결정: API 직접 연결과 설치된 에이전트 호출을 모두 지원하되 API 연결부터 구현합니다.
- 기존 v0.3.0 기록 명령과 스킬을 유지합니다. LLM 연결이 없어도 기존 명령은 동작해야 합니다.
- 단순 채팅 기능이나 제안 출력만으로 전체 목표를 완료 처리하지 않습니다.
- 첫 실행 범위는 로컬 프로젝트의 실험 하나입니다. 대회 제출, 원격 분산 실행, 무제한 자율 반복은 포함하지 않습니다.

## 사용자 흐름

아래는 장기 목표 흐름입니다. 현재 명령은 [사용법](research-api.md)에 명시한 단일 세션 흐름입니다. 현재 `setup`은 정해진 질문으로 사용자 설정을 수집하며 첫 계획의 승인 대기에서 멈춥니다. 자유로운 자연어 설정 자동 완성, 모델 생성 명령 및 비용 추정은 지원하지 않습니다.

1. 연결 프로필에 공급자 종류, 서버 주소, 모델, API 키를 읽을 환경변수 이름을 지정합니다.
2. 프로젝트를 열고 자연어로 목표와 시간·횟수·변경 범위를 지정합니다.
3. CLI가 외부로 전송할 파일 범위와 대상 서버를 보여줍니다. 허용된 코드와 제한된 기록 맥락을 LLM에 전달하고, 부족한 설정은 대화로 채웁니다.
4. LLM이 실험 가설, 비교 기준, 변경 diff, 실행 명령, 예상 비용의 불확실성을 제시합니다.
5. 사용자가 구체적인 변경과 실행을 승인하면 CLI가 변경을 적용하고 실험 한 번을 실행합니다.
6. CLI가 종료 상태·로그·설정된 지표 파일을 수집합니다. LLM은 관측을 바탕으로 유지·폐기·보류를 제안합니다.
7. 다음 세션에서 실험 상태를 복원합니다. 실행 중인지 불명확하면 확인 전 재실행하지 않습니다.

## 구성과 책임

| 구성 | 책임 |
|---|---|
| 연결 프로필 / API 어댑터 | 인증, 모델 호출, 제한된 재시도, 응답·사용량 정규화 |
| 세션 진행부 | 대화, 맥락 구성, 계획 초안, 승인 대기, 예산과 종료 조건 |
| 제한된 도구 실행부 | 파일 읽기, diff 검토·적용, 승인된 로컬 명령 실행 |
| 기존 기록 코어 | 검증된 기록 생성·전이, 비교, 근거 해시, 계보·재개 |
| 외부 에이전트 연결부 (후속) | 설치된 에이전트 호출 및 실행 결과 수집, 지원 기능 확인 |

API 연결부와 외부 에이전트 연결부를 같은 HTTP 인터페이스로 강제하지 않습니다. 연결 방식과 무관하게 계획·승인·관측·기록의 계약을 공유합니다. 기존 CLI를 매번 하위 프로세스로 호출하는 대신 검증 로직을 재사용하는 내부 서비스 경계를 두되, 필요한 범위만 분리합니다.

## 역할별 스킬과 루프 제어

공개 v0.3.0은 하나의 `ziho-autoresearch` 스킬과 CLI 레시피로 구성됩니다. 개발 구현은 번들 안의 references/roles 지침 7개를 역할별로 읽어 system 메시지에 주입합니다. 맥락은 별도 user JSON이며 신뢰할 수 없는 데이터로 취급합니다. 외부 에이전트의 스킬 탐색 기능이 없는 API 모델에도 CLI가 역할 지침을 명시적으로 전달해야 합니다. 파일을 설치하는 것만으로 역할 수행이 보장되지는 않습니다.

| 역할 | 입력 | 필수 출력 | 허용 작업 |
|---|---|---|---|
| 프로젝트 분석 | 사용자 목표, 허용된 코드·설정, 현재 기록 | 프로젝트 지도, 누락 설정, 확인 사실·불확실성 | 허용 파일·기록 읽기, 확인 질문 |
| 평가 검토 | 데이터·분할·지표 정의, 기준 실험, 후보 diff | 근거가 있는 판정, 적용 범위, 차단 사유·추가 검사 | 읽기, 별도 승인된 작은 검사 요청 |
| 실험 설계 | 검토 결과, 비교 가능한 기준, 실패 기억, 예산 | 단일 가설, 선택 근거, 비교 조건, 예상 변경·실행 계획 | 후보·계획 초안 생성 |
| 구현 | 검토된 계획, 허용 경로, 작업 상태 | 구체적인 diff, 영향 범위, 확인 방법 | 변경안 작성, 승인된 변경만 적용 |
| 변경 검토 | 원문 코드·변경 제안·평가 조건·계획 | pass/hold/invalid와 근거·불확실성 | 제안 읽기, 실행 권한 없음 |
| 결과 해석 | 실행기가 수집한 로그·지표, 비교 결과, 검토 근거 | 관측과 추론 구분, keep/discard/hold 제안, 한계 | 읽기와 판단 초안 생성 |
| 기억·다음 행동 | 확정된 결과·판단, 기존 실패 기억, 남은 예산 | 재사용 조건·한계가 있는 기억 초안, 다음 가설 또는 종료 이유 | 기억·다음 행동 초안 생성 |

현재 역할은 읽기·제안만 수행하며 파일 조회와 모든 실행은 CLI가 처리합니다. 실험 프로세스 시작·중단·로그 수집은 LLM 스킬이 아니라 실행기의 책임입니다. 역할별 스킬은 허용된 도구로 요청하며, 관측·판단 기록 저장은 기존 검증 코어를 통과합니다. 역할 출력과 기억 제안은 별도 세션 상태이며 자동으로 canonical 실패 기억이 되지 않습니다. 루프 제어기는 상태·승인·입력 버전·예산을 확인하고 실행기를 호출합니다. LLM이 성공 또는 승인이라고 출력해도 권한이나 실행 사실이 생기지 않습니다.

### 역할 호출 계약

각 호출은 역할 ID·지침 버전, 세션/후보/실험 ID, 입력 snapshot과 코드·설정 식별자, 근거 참조, 허용 도구, 호출·시간 예산을 받습니다. 역할별 출력 스키마에 사실·가설·근거·미확인 사항·요청 행동을 분리합니다. 코드가 역할과 상태에 맞는 요청인지 검증하고, 모르는 필드·부족한 근거·오래된 입력·권한 밖 요청은 실행 전에 거부합니다.

전체 대화와 모든 스킬을 매번 전달하지 않습니다. 해당 역할 지침과 필요한 기록을 선택해 주입하고 원문은 근거 참조로 조회합니다. 코드·로그에 포함된 지시문은 역할 지침이나 권한으로 승격하지 않습니다. 모델이 구조화된 출력을 지원하지 않거나 계약을 위반하면 해당 호출은 실패합니다. 자동 재시도는 없으며 사용자가 advance를 다시 요청하면 호출 예산을 새로 소비합니다.

처음에는 같은 모델을 역할별 별도 호출로 사용할 수 있습니다. 역할 분리는 여러 모델이나 병렬 실행을 뜻하지 않으며, 같은 모델의 재검토를 독립적인 검증이라고 부르지 않습니다. 검토 단계에는 제안자의 결론만 넘기지 않고 원문 diff·조건·근거를 제공합니다. 모델별 역할 배정은 후속 확장입니다.

### 단계 전환과 되돌아가는 경로

기준 확보는 `baseline` 모드에서 모델 변경 없이 현재 원본을 실행하고 실제 관측·명시적 keep·선택을 거칩니다. 후보는 호환되는 선택 기준을 확인한 뒤 시작합니다. 선택은 파일 복원이 아니며 실패·unknown을 기준으로 삼지 않습니다. 모드가 없는 과거 세션의 원본 무변경 여부를 소급 보증하지 않습니다.

정상 경로: 분석 → 평가 검토·유효 기준 확보 → 실험 설계 → 변경안 작성 → 변경 검토 → 사용자 승인 → 실행 → 관측 확인·비교 → 결과 해석 → 판단 확정·기억 → 종료. 다음 실험은 새 세션과 승인이 필요합니다.

- 설정 누락: 분석 단계에서 필요한 정보를 확보하며 실행은 대기합니다.
- 평가 무효·비교 조건 변경: 성능 탐색을 멈추고 평가 수정·새 기준 확보로 돌아갑니다. LLM의 통과 판정만으로 ML 타당성이 입증되지는 않습니다.
- 계획과 diff 불일치·승인 후 입력 변경: 변경 검토로 돌아가고 기존 승인을 실행에 재사용하지 않습니다.
- 승인 거절: 적용·실행하지 않고 계획 수정 또는 종료로 이동합니다.
- 실행 실패: 실제 실패 근거를 남기고 한도 내 수정안을 만듭니다. 새 실행에는 새 ID와 유효한 승인이 필요합니다.
- 실행 불명: unknown을 유지하고 프로세스·로그 확인 경로로 이동합니다. 해소 전 같은 실행을 반복하지 않습니다.
- 지표·근거 누락: 추가 확인 또는 hold로 전환합니다. LLM이 예측한 점수로 채우지 않습니다.
- 예산 소진·사용자 중단: 새 호출·실행을 시작하지 않고 상태와 재개 방법을 남깁니다.

첫 버전은 실행마다 구체적인 변경·명령을 승인받습니다. 판단·선택 변경도 사용자 확인 후 반영하며, 코드 복원은 별도 명시된 작업입니다. 이후 반복 실행 위임을 지원하더라도 승인 범위와 예산을 별도로 정의해야 합니다.

### 역할·루프 검증

역할 지침을 읽었다는 응답만으로 통과하지 않습니다. 호출 추적으로 역할·버전·입력 참조·도구 요청·게이트 결과를 확인하며 키와 불필요한 원시 대화는 저장하지 않습니다. 실험 관측의 원본은 기존 기록에 두고, 세션 제어 상태는 이를 참조하며 점수·판단 원본을 중복 관리하지 않습니다.

검증에는 다음을 포함합니다: 각 역할의 허용 도구 밖 요청 차단, 계획 단계의 실행 시도 차단, 조작된 성공 점수 거부, 오래된 검토·승인 거부, unknown 중복 실행 차단, 정상 루프의 최종 기록 일치. API와 외부 에이전트 연결 모두 같은 계약을 지켜야 합니다. 외부 에이전트에서 실행 권한을 제한할 수 없다면 해당 모드는 제안 전용으로 제공하고 승인 실행 지원으로 표시하지 않습니다.

## 대화형 설정의 현재 계약

`research setup --project <기존 폴더>`는 목표·비교 조건·환경·예산·명령·파일 허용 범위·API 연결·지표 설정을 묻습니다. 실행 인자는 개별 입력으로 수집하고 셸 문자열을 해석하지 않습니다. 키 값은 입력받지 않으며 환경변수 이름만 저장합니다. 학습 프로그램과 평가 조건은 사용자가 준비합니다.

설정 저장과 API 전송은 별도 확인이며 기본값은 거절입니다. 저장 전 취소에는 쓰기가 없고, 저장 후 전송 거절에는 설정·세션이 남습니다. 전송 동의 후 5개 계획 역할이 유효하면 `awaiting_approval`에서 종료합니다. 승인·실행·판단 단계는 기존 세션 명령을 따릅니다. 기존 프로젝트 ID·기록·선택을 보존하고 설정 중 동시 변경을 검출하며, 비교 조건 변경에는 새 비교 ID를 요구합니다. 입력은 TTY가 필요하고 JSON 모드의 질문은 stderr로 출력합니다.

실행 전 추가 질문·계획 수정은 `research revise <세션 ID>`로 제공합니다. 누락 질문 답변과 피드백, 검토한 설정을 새 계획에 전달하고 분석부터 다시 시작합니다. 기존 제안은 이전 기록에 보존하되 승인 토큰을 제거하며 실행 권한을 계승하지 않습니다. 실험 ID가 없는 planning/blocked/rejected/awaiting_approval/approved만 대상이며 적용 중단을 복구한 세션은 제외하며 실행 후 수정안·unknown 해소를 대신하지 않습니다. [수정 계약](research-api.md#추가-질문과-계획-수정)을 따릅니다.

완료된 실험의 다음 계획은 `research next <세션 ID>`로 제공합니다. TTY에서 이전 설정을 검토하고 새로운 목표·지표 출력 경로를 지정하며 저장·전송·계획 승인을 새로 확인합니다. 이전 완료 세션은 보존하고 실제 확정 판단·관측과 기억 제안을 제한된 맥락으로 전달합니다. 이전 실험을 자동 선택하거나 파일을 복원하지 않습니다. 부모 세션의 연결과 선택된 비교 기준은 별개입니다. 실행 명령이 새 지표 경로에 쓰도록 사용자가 설정해야 하며 임의 명령 인자는 자동 변경하지 않습니다. [기준·다음 실험 계약](research-api.md#완료된-실험에서-다음-실험으로-이어가기)을 따릅니다.

## 첫 API 연결 범위

첫 어댑터는 OpenAI 호환 Chat Completions 형식으로 구현했습니다. 실제 공급자와의 연결은 미검증입니다. 모델과 base URL을 지정하고 응답 형식·종료 사유를 검사합니다. 사전 공급자 호환성 탐지 기능은 없습니다. 모든 공급자가 이 형식을 지원한다고 가정하지 않습니다. 공급자별 네이티브 API는 별도 어댑터로 추가합니다. 구현 시 선택한 공급자의 공식 API 문서를 확인합니다.

API 키 값은 환경변수에서 읽고 프로젝트 JSON·Git·보고서에 저장하지 않습니다. 프로필에는 환경변수 이름만 저장합니다. 인증 헤더를 로그에서 제외하고, 원시 응답에는 민감한 내용이 있을 수 있으므로 무조건 영구 저장하지 않습니다. 외부 전송은 기본적으로 승인된 코드·설정과 제한된 기록에 한정하고 데이터셋 전체·환경 파일을 자동 첨부하지 않습니다.

타임아웃·잘못된 응답·연결 오류를 구분하며 인증 실패와 요청 제한은 HTTP 상태 코드로 표시합니다. 서버 오류 본문과 인증 헤더는 출력하지 않습니다. 응답이 계획 형식에 맞지 않으면 실행하지 않습니다. 호출 횟수·호출별 출력 토큰·세션 시간 한도를 두고, 공급자가 사용량을 반환하지 않으면 미확인으로 기록합니다. 가격 정보가 없는 경우 금액 한도를 정확히 보장한다고 표시하지 않습니다.

## 승인과 실행

- 승인은 특정 diff·명령·작업 경로·환경·예산에 연결합니다. 승인 후 입력이나 파일이 바뀌면 다시 검토합니다.
- LLM 출력은 제안입니다. 임의 텍스트를 셸 명령으로 자동 실행하지 않습니다. 실행 명령은 구조화된 인자와 명시된 작업 디렉터리로 전달합니다.
- 기존 사용자 변경을 보존합니다. Git reset이나 자동 커밋·push를 기본 동작으로 넣지 않습니다.
- 허용 경로 검사는 학습 코드 전체에 대한 OS 샌드박스를 뜻하지 않습니다. 로컬 실행 권한과 한계를 명확히 표시합니다.
- 명령 시작 전 실행 의도를 영속 기록하고 실행 식별자·로그 경로를 연결합니다. 긴 실행 동안 기록 잠금을 계속 점유하지 않습니다.
- 종료 코드 0만으로 점수나 성공을 추정하지 않습니다. 명시한 지표 파일·키·유효 숫자·비교 조건을 확인합니다. 미확인 결과는 성공으로 기록하지 않습니다.
- Ctrl-C 시 종료 요청과 확인 결과를 구분합니다. CLI 자체가 종료되거나 자식 프로세스 상태를 확인할 수 없으면 unknown으로 남깁니다. PID만으로 재실행 안전성을 판정하지 않습니다.
- API 실패를 재시도하더라도 실험 실행을 중복 재시도하지 않습니다. 세션·승인·실행 ID로 이전 진행을 확인합니다.

## 구현 순서와 완료 조건

| 순서 | 산출물 | 완료 증거 |
|---|---|---|
| 1 | 연결 설정과 API 호출 구현, 프로젝트 읽기, 계획 초안; 실제 클라우드 미검증 | 잘못된 인증·타임아웃·응답 형식 검사, 실제 API로 계획 생성, 실행은 발생하지 않음 |
| 2 | 승인된 diff 적용과 로컬 실험 하나 실행·기록 구현 | 거절 시 변경·실행 없음, 승인 내용 일치, 실제 로그·지표와 저장 기록 일치 |
| 3 | 중단·재개와 예산 종료 구현 | 프로세스 강제 종료·통신 장애 후 중복 실행 없음, unknown 보존·근거 기반 해소 |
| 4 | 설치된 Codex·Claude Code 연결 — 후속 미구현 | 설치된 버전의 공식 호출 방식 확인, 실제 에이전트별 동일 실험 흐름 검증 |

1~3이 API 기반 최소 제품의 목표입니다. 현재 코드 구현과 모의 검증이 실제 API·ML 실사용 검증 완료를 뜻하지 않습니다. 1만 완료한 상태를 실험 실행 도구 완성으로 발표하지 않습니다. 4까지 사용자가 선택한 두 연결 방식을 모두 지원합니다.

## 검증과 제품 판단

회귀 검사는 가짜 공급자와 작은 결정적 실행 프로그램으로 실패·중단·중복 요청을 재현합니다. 기존 기록 계약과 CLI 사용법을 유지하는지 검사합니다. 실제 API 검증은 사용자가 지정한 엔드포인트·환경변수·예산으로 수행하며 자격증명이 없으면 미검증으로 표시합니다.

마지막에는 설치한 패키지와 작은 공개 또는 합성 ML 데이터로 baseline → 변경 → 실행 → 비교 → 재개를 수행합니다. 사용자의 수동 JSON 편집 없이 완료되는지, 기록된 수치가 실제 결과와 같은지 확인합니다. 학습 점수 상승 자체를 기능 통과 조건으로 삼지 않습니다.

기존 에이전트+Git 방식과 비교할 항목은 완료 시간, 사용자 개입, 기록 누락, 재개 오류, API·실험 사용량입니다. 도구의 복잡성이 늘어난 만큼 효용이 생겼는지를 이 근거로 평가합니다.
