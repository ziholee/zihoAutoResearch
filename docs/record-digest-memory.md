# 기록 해시의 문자열·UTF-8 일시 메모리

2026-10-22 · 합성 기록·모의 공급자 기준이며 실제 API나 학습 성능은 검증하지 않습니다.

## 원인과 변경

기존 연구 기록 식별자는 모든 기록을 `dumps(records)`로 한 번에 문자열로 만들고 UTF-8로 변환한 뒤 SHA256에 전달했습니다. 전체 문자열 조립과 인코딩 중 큰 중간 값들이 함께 존재했습니다. 기록을 64개씩 기존 codec으로 직렬화하고, 외부 괄호와 마지막 개행만 제거해 같은 순서로 SHA256에 전달합니다. 새 기록 전용 `records_digest`를 사용하며 일반 `digest`와 `codec.dumps`는 변경하지 않습니다.

그룹·식별자의 삽입 순서, 키 검증, Decimal과 Unicode, 구분자 공백 및 마지막 개행을 유지합니다. 전체 바이트 연결 결과와 SHA256가 이전 형식과 같으므로 기존 저장 세션의 기록 해시 형식을 바꾸지 않습니다. 새 캐시나 파일 검사 생략은 없습니다. 연구 시작·호출 전후 검사·기록 식별자 조회·다음 세션 연결에서 같은 경로를 사용합니다.

한 배치에 최대 64개 문서의 참조를 담습니다. 문서 내용을 복사하거나 호출 사이에 보관하지 않습니다. **항목 수 제한이며 바이트 상한은 아닙니다.** 단일 큰 문서와 전체 파싱된 기록 스냅샷은 여전히 메모리를 사용합니다.

## 후보 선택

사전 진단에서 문서 한 개씩 전달하는 방법은 encoder 생성과 해시 갱신 호출이 늘어 느렸습니다. 64개 묶음은 기존 codec을 재사용하면서 중간 문자열 크기를 줄이고 호출 비용도 제한했습니다. 진단 수치와 정식 결과를 섞지 않으며, 아래 교차 측정으로 최종 효과를 확인합니다.

## 재현과 측정 범위

기준 소스는 `a4d5b36`의 별도 사본입니다. 모든 출력 폴더는 새 경로여야 합니다.

```sh
python3.11 scripts/profile_record_digest.py --before /tmp/before --after . --output /tmp/digest-memory --records 100 10000 --repeats 3
python3.11 scripts/benchmark_crossed_research.py --before /tmp/before --after . --output /tmp/crossed-loop --repeats 3
python3.11 scripts/verify_mixed_research.py --source . --output /tmp/digest-verification
```

단독 도구는 동일한 검증된 기록을 로드한 뒤 실제 `records_digest`를 호출합니다. 기준 소스에 함수가 없으면 기존 `digest`를 호출합니다. control 시간과 별도 tracemalloc 실행을 구분합니다. 시작·로딩·검증·결과 저장은 시간에 포함하지 않으며, 추적 할당은 이미 로드한 스냅샷이나 RSS를 포함하지 않습니다.

바이트 수집은 측정 종료 후 두 번째 호출에서 SHA256의 생성·갱신 입력을 private 파일로 순서대로 기록합니다. 계측 중에는 조각 원문을 모아두지 않습니다. 부모 프로세스가 전후·모든 반복의 바이트를 직접 비교하며 SHA256도 대조합니다.

전체 루프는 작은 조건(100개 기록·세션 0개)과 혼합 조건(10,000개 기록·완료 세션 2,500개·기억 본문 16,000자)을 사용합니다. 각 조건·계획/조회/재개마다 준비 1쌍 뒤 **전→후, 후→전, 전→후**의 3쌍을 측정합니다. 각 표본은 새 프로세스·공통 fixture의 독립 사본을 사용합니다. 기존 worker와 보호 절차 검증기를 재사용합니다.

CLI 시간은 Python 시작·CLI·출력·저장 토큰 검사·메타데이터·종료를 포함하고 fixture 생성·복사·재개 준비·부모 검증은 제외합니다. RSS는 자식 프로세스 최고치입니다. 재개는 성공 역할 2개를 저장하고 모의 요청을 중단한 뒤 새 프로세스가 남은 역할 3개만 수행하는 조건입니다. OS 강제 종료나 실제 학습의 성능을 측정하지 않으며 기존 unknown·복구 회귀 검사는 유지합니다.

정식 측정 동안 다른 테스트·빌드를 실행하지 않습니다. 소스·도구·입력 해시, 최근 기억·역할·예산·승인·CLI 의미·원본 보존을 확인합니다. 공개 보고서에는 수치·해시만 포함하며 원문은 실행 폴더의 `private/`에 둡니다.

## 기록 해시 단독 결과

Python 3.11.17·Darwin arm64, 각 항목 3회 중앙값입니다. [단독 원시 표본](benchmarks/record-digest-memory.json)을 제공합니다. control 시간과 별도 allocation 최고치는 서로 다른 실행입니다.

| 기록 수 | control 전→후(초) | 추적 할당 최고 전→후(bytes) | 최대 SHA256 입력 조각 전→후(bytes) |
| --- | ---: | ---: | ---: |
| 100 | 0.001857 → 0.001920 | 548,995 → 354,514 | 112,306 → 71,827 |
| 10,000 | 0.199426 → 0.175563 | 54,785,665 → 410,920 | 11,221,990 → 71,827 |

10,000개에서는 추적 임시 할당 최고가 약 52.25MiB→0.39MiB로 줄었고 control 시간은 약 12.0% 짧았습니다. 100개 단독 시간은 약 0.063ms 늘어 모든 입력의 속도 향상을 주장하지 않습니다. SHA256에 전달된 전체 바이트는 100개 112,306bytes, 10,000개 11,221,990bytes로 전후·모든 반복·계측 모드에서 직접 비교로 일치합니다. 최대 조각 크기는 이 fixture의 관측값이며 보장하는 바이트 상한이 아닙니다.

## 전체 루프 교차 결과

[전체 표본·실행 순서·쌍별 차이](benchmarks/record-digest-crossed.json)를 제공합니다. 각 값은 3회 중앙값으로, 시간과 RSS를 별도로 계산합니다. 전후 중앙값 차이와 쌍별 차이의 중앙값은 같지 않을 수 있습니다.

| 조건 | 작업 | 시간 전→후(초) | 최고 RSS 전→후(MiB) |
| --- | --- | ---: | ---: |
| 100개 기록·세션 0개 | 계획 | 0.1833 → 0.1847 | 37.98 → 37.77 |
| 100개 기록·세션 0개 | 조회 | 0.0892 → 0.0874 | 35.95 → 36.19 |
| 100개 기록·세션 0개 | 재개 | 0.1513 → 0.1444 | 37.88 → 37.80 |
| 10,000개 기록·큰 기억 2,500개 | 계획 | 10.6352 → 10.5406 | 301.64 → 119.02 |
| 10,000개 기록·큰 기억 2,500개 | 조회 | 0.1288 → 0.1209 | 35.92 → 36.12 |
| 10,000개 기록·큰 기억 2,500개 | 재개 | 5.7641 → 5.6512 | 227.56 → 118.47 |

혼합 계획의 쌍별 후−전 시간은 −0.3716·−0.0945·+0.3662초, 재개는 −0.0186·−0.1667·+0.1249초로 부호가 섞였습니다. 작은 계획도 중앙값이 약 1.4ms 늘었습니다. 관측된 일관된 효과는 대규모 조건의 메모리 감소이며, 모든 작업의 속도 개선을 주장하지 않습니다.

혼합 계획 RSS는 세 쌍에서 각각 182.62·176.41·182.62MiB, 재개는 108.95·109.09·129.09MiB 낮았습니다. 이는 프로세스 전체의 최고 RSS 차이입니다. 단일 해시 호출의 추적 임시 할당 감소와 직접 더하거나 같은 양으로 해석하지 않습니다. 파싱된 전체 기록과 세션 기억 등 필요한 메모리는 여전히 남습니다.

총 36개 측정 표본과 12개 준비 실행이 전후 의미·원문 보존 검증을 통과했습니다. 계획은 기록 로드 11회/모의 호출 5회, 조회는 0회/0회, 재개는 6회/3회로 전후 같습니다. 원문 확인이나 호출 전후 변경 검사를 생략해 얻은 효과가 아닙니다.

## 검증과 한계

배치 경계 전후 0·1·63·64·65·128·129·1,000개, 빈 그룹, 역순 식별자, Decimal·Unicode·이스케이프, 단일 큰 문서, 잘못된 키/숫자/Unicode를 검사합니다. 기존 구현은 1,000개에서 전체 입력을 한 조각으로 전달해 메모리 경로 회귀가 실패하고, 변경 후 작은 조각으로 나뉘며 동일 바이트·해시를 유지합니다.

전체 475개 테스트와 [혼합 조건 기능 9개 시나리오](benchmarks/record-digest-verification.json)가 통과했습니다. 같은 크기·mtime 수정, 기록 추가·삭제·정정, 역할 사이 변경, 최근 기억 수정·추가·삭제, 별도 프로세스 재개, 승인 전 실행 거부와 오래된 입력의 승인 거부를 확인했습니다.

한 로컬 환경·합성 자료·따뜻한 파일 캐시·소수 반복의 관측입니다. 실행 순서 교차가 모든 환경 변동을 제거하거나 통계적 유의성을 보장하지 않습니다. 속도·RSS·추적 할당을 별도로 해석하며 캐시 한도 확대나 파일 검사 생략의 근거로 사용하지 않습니다.

후속 [큰 기록 배치 검증](large-record-batches.md)은 큰 문서·크기 편차가 있는 63·64·65개 경계와 혼합 조건을 확인합니다.
