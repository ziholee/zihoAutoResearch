# 연구 세션의 실행·전송 계약과 신뢰 경계

이 문서는 미배포 개발 소스의 `research` 기능에 적용합니다. 공개 v0.3.0은 기록·검증 CLI와 스킬을 제공하며 직접 LLM 호출과 실험 실행을 제공하지 않습니다. 명령 사용법은 [연구 API 안내](research-api.md)를 참고하세요.

## 보호하는 것과 보호하지 않는 것

승인 토큰은 검토한 제안·입력의 해시입니다. 사람의 신원을 확인하는 서명이나 인증 자격증명이 아닙니다. `--send`, `approve --token`, `run`, `decide --token`은 명시적 절차를 요구하지만, 같은 사용자 권한으로 CLI를 호출할 수 있는 프로세스와 사람을 구별하지 않습니다.

프로젝트 설정, 세션 파일, CLI 설치물은 로컬 운영자가 관리하는 상태입니다. 이들을 모두 수정할 수 있는 주체는 해시와 상태도 다시 만들 수 있습니다. 새 연결 프로필 해시 역시 같은 신뢰 경계 안의 변경 감지이며, 악의적인 동일 권한 프로세스에 대한 위조 방지가 아닙니다. 이 경계가 필요하다면 승인 주체와 실행 주체의 OS 권한·비밀 저장소부터 분리해야 합니다. 같은 사용자에게 읽히는 HMAC 키나 TTY 입력만으로 사람 승인을 증명할 수는 없습니다.

API 모델은 도구 없이 역할별 JSON 제안을 반환합니다. 허용된 소스 수정도 명시적 실행 승인 뒤에 적용합니다. Codex 연결 제한은 제안 공급자에 적용되며, 이후 실행하는 학습 프로세스를 격리하지 않습니다.

## 실행 직전 재검증

세션에 저장된 명령은 현재 `project.json`에 등록된 명령 하나와 이름·인자·작업 디렉터리 모두 일치해야 합니다. 프로젝트 해시가 같다는 사실만으로 세션의 명령을 신뢰하지 않습니다.

`run`은 파일을 쓰거나 실행 의도를 기록하기 전에 구현 제안의 형식, 정확한 수정 허용 경로, 전송된 소스 범위, 원본 해시, 크기 제한을 다시 검사합니다. 기준 실험은 변경 없이 실행해야 합니다. 승인 토큰을 다시 계산해도 이 검사들을 생략할 수 없습니다. 유효한 실행은 기존과 동일하게 한 번만 시도하며, 실행 여부가 불명확하면 `unknown`과 기존 복구 절차를 유지합니다.

이 검사는 평가 코드의 과학적 타당성, 점수의 진실성, 전체 의존 파일의 동일성을 증명하지 않습니다. 현재 소스 식별자는 명시적으로 선택한 파일 범위입니다. 선택한 고정 평가·추가 입력 파일은 [평가 보호와 출처 검증](evaluation-provenance.md)을 활성화해 별도로 확인할 수 있습니다. 선택하지 않은 파일과 점수의 진실성까지 보장하지는 않습니다.

## 전송 프로필 고정

새 세션은 `transmission_contract` 버전 1에 정규화된 연결 프로필의 해시를 저장합니다. API의 목적지·모델·키 환경변수 이름과 요청 제한, Codex의 실행 파일 설정·모델·제한이 대상입니다. 키 값 자체는 저장하거나 해시하지 않습니다. 같은 환경변수의 키 교체를 감지하는 기능도 아닙니다.

각 호출 전후에 고정 프로필을 검사합니다. 응답을 받으면 디스크에서 다시 읽은 세션이 실제 요청을 보낸 상태와 같은지도 확인합니다. 호출 중 변경을 발견하면 응답을 다음 단계에 적용하거나 다음 역할을 호출하지 않습니다. 이미 전송된 요청을 취소하거나 외부 처리·과금을 되돌릴 수는 없습니다.

조회 결과의 `transmission.contract_status`는 `pinned` 또는 `legacy_unpinned`입니다. 이는 고정 정보 필드의 존재 여부이며 검증 성공 표시가 아닙니다. 형식과 현재 프로필 해시의 일치는 실제 동작 직전에 검사하며 불일치하면 차단합니다. API 프로필에서는 키 환경변수 이름도 확인할 수 있지만 값은 출력하지 않습니다. 전송 전 목적지·모델·키 환경변수 이름·파일 범위를 검토하세요. 연결을 바꿀 때 세션 JSON이나 해시를 직접 고치지 말고, 가능한 상태에서는 `revise`로 새 세션을 만들거나 새 `start`를 사용하세요. `next`·`revise`의 설정 검토와 저장·전송 동의는 그대로 필요합니다.

## 구버전과 중단 복구

`transmission_contract`가 없는 과거 세션은 `legacy_unpinned`로 표시하고 기존 승인 토큰과 복구 절차를 유지합니다. 조회나 재개 중 자동으로 새 계약을 붙여 과거에 연결이 고정돼 있었다고 주장하지 않습니다. 이런 세션은 최초 연결 프로필과의 일치를 확인할 수 없습니다. 전송 전에 현재 프로필을 직접 검토하거나 새 세션으로 옮기세요. 명령 재대조와 현재 호출 중 세션 변경 검사는 과거 세션에도 적용됩니다.

기존 `calling`·`applying`·`executing`·`unknown` 상태를 연결 변경의 우회 경로로 사용하지 않습니다. 실제 프로세스 종료와 실행 근거를 확인하고 해당 `recover` 또는 `reconcile` 절차를 따르세요. 복구가 새로운 실행 승인이나 자동 재전송을 뜻하지는 않습니다. 역할 변형 비교도 부모 세션의 검사와 별도 승인·전송 절차를 따릅니다.

## 로컬 실행의 한계

학습 명령은 셸 없이 제한된 환경변수로 실행하지만 OS 샌드박스가 아닙니다. 실행 프로그램은 사용자 권한으로 파일·자격증명 저장소·네트워크에 접근할 수 있습니다. 읽기·수정 허용 목록은 CLI가 제안에 적용하는 제한이며 프로그램 전체의 파일 접근 제어가 아닙니다. 동일 모델의 검토도 독립적인 보안 또는 ML 검증을 대체하지 않습니다.

검증은 임시 프로젝트, 무해한 실행 표시 파일, 루프백 모의 서버와 합성 자격증명을 사용합니다. 실제 공급자 연결, 악성 코드 격리, 사람 인증, 실사용 ML 품질은 검증하지 않습니다.
