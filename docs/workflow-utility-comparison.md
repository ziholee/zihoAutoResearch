# 직접 실행+Git과 zar의 도구 효용 비교

이 문서는 개발 소스의 **자동화된 두 작업 경로**를 비교하는 프로토콜과 측정 범위를 설명합니다. 사람이 수행한 사용자 연구나 실제 LLM을 사용한 실험이 아닙니다. 모의 공급자의 정해진 제안과 작은 합성 회귀 문제로 실행·기록·재개의 동작 및 부가 비용을 비교합니다.

## 공통 조건

| 요구 | 두 경로에 적용하는 조건 |
|---|---|
| 데이터·후보 | 같은 학습/평가 데이터, 평균 예측 기준 모델과 선형 회귀 후보, 고정 평가기의 MSE |
| 모델 공급자 | 같은 정해진 역할 응답을 반환하는 로컬 모의 HTTP 공급자. 실제 API·Codex 호출 없음 |
| 승인 | 동일한 제안에 대해 실행 승인과 판단 확정을 각각 기록. 하네스의 자동 승인이며 사람의 행동 횟수가 아님 |
| 실행·기록 | 기준·후보 각각 1회 실행, 계획·소스 식별·지표·근거·판단 기록 |
| Git | 각 경로의 별도 저장소에 소스와 완료 기록을 같은 이정표에서 커밋. 시험용 이름·이메일 사용 |
| 중단·재개 | 후보 결과가 저장된 지점에서 작업 프로세스 종료, 새 프로세스에서 조회·판단을 이어가며 학습 재실행 없음 |
| 확인 | 별도 검증에서 원자료·계산 결과·근거 해시·기록·실행 횟수를 대조. 빨라야 통과하는 조건은 없음 |

직접 실행+Git 경로는 이 시험에 필요한 기록·승인·재개 절차를 갖춘 별도 하네스입니다. 아무 기록도 남기지 않는 단순 학습 명령을 비교군으로 삼지 않습니다. 그렇다고 이 하네스가 범용 CLI의 입력 검증·오류 처리·호환성·잠금 보장까지 제공하는 제품인 것도 아닙니다.

두 경로 모두 각 실행 직후 소스 스냅샷, 판단 완료 후 근거·기록을 커밋합니다. 소스 커밋은 실행 전의 Git 이력이라는 뜻이 아닙니다. 실행에 연결된 소스 해시와 이후 Git 스냅샷의 일치를 별도로 확인합니다.

zar 경로는 공개 `research` 명령을 사용합니다. 모의 응답이 같아도 두 경로가 구성하는 요청 맥락과 관리 기록은 다를 수 있습니다. 이 차이를 모델 성능의 차이로 해석하지 않으며, 원자료에 호출과 명령을 남깁니다.

## 실행과 측정

개발 소스를 설치한 Python 환경과 Git이 필요합니다. 공개 v0.3.0으로는 이 개발용 비교를 실행할 수 없습니다.

```sh
python -m pip install .
python scripts/benchmark_workflow_utility.py --output ./utility-results --repeats 3
```

출력 디렉터리는 새 경로여야 합니다. 반복마다 먼저 실행하는 경로를 교대합니다. 시간은 벽시계 관측치이며 기기·부하·파일시스템·프로세스 시작 비용에 영향을 받습니다. 적은 반복의 중앙값은 신뢰구간이나 통계적 우월성의 근거가 아닙니다.

명령 수에는 무엇을 세었는지 구분해야 합니다. 하나의 zar 명령 내부에서 여러 역할 호출이나 파일 작업이 수행될 수 있으므로, 명령 수를 작업 복잡도·사용자 노력으로 환산하지 않습니다. 승인 수 역시 하네스가 수행한 단계 수입니다. Git 기록과 실행 산출물의 양도 관리 범위가 다르면 달라집니다.

중단은 결과 저장 후의 안전한 지점입니다. 여기서 재실행이 없다는 결과를 강제 종료·불명 실행 복구 전반으로 확대하지 않습니다. 해당 검증은 [실제 CLI 장애 복구 예제](crash-recovery-validation.md)를 참고하세요.

## 해석의 한계와 검증 독립성

`mandela` 스킬의 검증 독립성 관점에서 주의할 부분은 **Verifier = designer**입니다. 두 경로의 하네스와 요구를 같은 프로젝트에서 설계했으므로, 내부 시나리오 통과만으로 실제 사용자의 편익을 증명할 수 없습니다. 원자료와 공개 프로토콜, 별도 계산·변조 회귀 검사와 독립 리뷰로 동작을 대조하되, 실제 사람의 작업 시간·판단 품질·기록 실수 감소는 후속 사용자 관측이 필요합니다.

합성 데이터와 후보를 미리 정했으므로 LLM의 가설 생성 능력·일반화 성능도 검증하지 않습니다. 실제 토큰·금액·서비스 지연은 측정하지 않으며, 모의 호출 결과로 추정하지 않습니다. 직접 경로에 필요한 하네스 작성·유지 비용도 이번 실행 시간에 포함되지 않습니다. zar 개발·유지 비용 역시 포함되지 않습니다.

결론은 다음을 구분해 기록합니다.

- 이 고정 시나리오에서 두 경로가 같은 필수 산출물과 복구 조건을 만족했는가.
- 관측된 실행 시간·명령·호출·승인 단계 수에 어떤 차이가 있었는가.
- 범용 도구의 기능과 시험용 하네스의 기능 차이가 해석을 어디까지 제한하는가.
- 아직 측정하지 않은 실제 사용자 효용과 공급자 호환성은 무엇인가.

실제 API 연결 검증은 후속으로 남깁니다. 측정 결과가 불리하더라도 숨기거나 비교군을 약화하지 않으며, 이번 변경에서 런타임 최적화를 함께 수행하지 않습니다.

## 로컬 측정 결과 — 2026-10-19

아래 수치는 당시 모의 서버의 종료 확인 간격 0.5초로 측정한 이력입니다. 현재 비교 하네스는 [로컬 비용 분해](local-loop-costs.md)에서 확인된 종료 대기를 줄이기 위해 0.01초를 사용합니다. 아래 원자료를 덮어쓰거나 제품 성능 향상으로 환산하지 않습니다.

macOS arm64, Python 3.11.17의 단일 로컬 환경에서 3쌍을 측정했습니다. 각 반복의 순서는 direct→zar, zar→direct, direct→zar입니다. 저장소의 회귀·빌드·설치 검사를 끝낸 뒤 별도로 실행했으며, 다른 시스템 부하는 통제하지 않았습니다. [반복별 원자료와 코드 해시](benchmarks/workflow-utility-results.json)를 제공합니다. 전체 명령·원본 기록·Git 저장소는 재현 명령의 출력 폴더에서 확인할 수 있습니다.

| 관측 항목 | 직접 실행+Git | zar+Git |
|---|---:|---:|
| 전체 벽시계 시간 중앙값 | 1.341초 | 2.306초 |
| 재개 단계 중앙값 | 0.050초 | 0.470초 |
| 반복당 실제 학습 실행 | 2회 | 2회 |
| 반복당 모의 공급자 요청 | 14회 | 14회 |
| 반복당 스크립트 실행·선택 승인 | 4회 | 4회 |
| 반복당 Git 커밋 / 명령 | 4회 / 13회 | 4회 / 13회 |
| 반복당 zar CLI 호출 | 0회 | 20회 |
| 필수 산출물·재실행 없는 재개 | 3쌍 모두 통과 | 3쌍 모두 통과 |

두 경로의 평가 MSE는 기준 **4.940894744681347**, 후보 **0.022256767659429855**로 같았습니다. 데이터·평가기·모델과 역할 응답이 같고, 실제 지표·기록·근거 파일·Git 내용·선택 ID가 일치하는지 검증했습니다. 점수 개선은 고정된 합성 문제의 성질이며 도구의 연구 능력을 뜻하지 않습니다.

이 시나리오에서는 zar의 전체 중앙값이 약 **0.965초 더 길었습니다**. zar를 쓰면 실행이 더 빨라진다는 근거는 얻지 못했습니다. 직접 경로의 14회 역할 호출과 파일 작업은 전용 Python 코드 내부에서 수행되고, zar 경로는 20회의 공개 CLI 호출과 관리 검사를 거칩니다. 두 방식 모두 사람이 입력한 명령 수가 아니며 이 수치로 작업 시간을 환산할 수 없습니다.

`total`은 두 worker 시작·파일 저장·모의 서버 종료를 포함합니다. 단계별 시간은 worker 안에서 측정하므로 단계 사이 저장·프로세스 전환·마지막 서버 종료 시간을 모두 포함하지 않으며, 단계 중앙값의 합이 전체 중앙값과 같지 않습니다. 산출물 검증기의 Git 조회와 점수 재계산은 측정 종료 후 수행하여 양쪽 총시간에서 제외합니다.

첫 쌍의 준비된 메시지 본문은 직접 경로 3,045바이트, zar 경로 120,730바이트였습니다. 같은 응답을 돌려주는 고정 모의 공급자이지만, 직접 경로는 최소 맥락을 보내고 zar는 역할 지침·소스·기록 맥락을 구성하기 때문입니다. 실제 전달 네트워크 크기·토큰·비용 또는 유효한 실제 모델 입력의 동등성을 뜻하지 않습니다.

현재 확인한 것은 **두 경로 모두 이 고정 작업을 완료할 수 있으며 zar 경로에는 측정 가능한 부가 시간이 있다**는 점입니다. 기록 규칙과 재개 검사를 여러 프로젝트에서 직접 작성하지 않아도 되는 가치가 실제로 작성·관리 시간이나 오류를 줄이는지는 아직 측정하지 않았습니다. 다음 검증은 실제 사용자 또는 실제 공급자 환경에서 같은 산출물 요구를 적용하는 것으로 남깁니다.
