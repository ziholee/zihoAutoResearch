# 실제 CLI 종료·재시작과 장애 복구 검증

개발 소스 전용 예제입니다. 공개 v0.3.0에는 필요한 `research` 명령이 없습니다. [학습·평가 예제](ml-loop-example.md)가 결과 저장 후의 안전한 재개를 다루는 반면, 이 예제는 호출 또는 실행이 진행 중인 실제 CLI 프로세스를 종료합니다. 외부 API·실제 Codex 추론은 호출하지 않습니다.

## 실행

현재 개발 소스에서 가상환경에 패키지를 설치한 뒤 실행합니다. Linux 또는 macOS와 Python 3.11 이상이 필요합니다.

```sh
python -m pip install .
python examples/crash-recovery.py --output ./demo-crash
```

출력 경로는 존재하지 않는 새 디렉터리여야 합니다. 예제는 자신이 만든 CLI·시험용 실행 프로세스만 제어합니다. 실제 프로젝트나 학습 프로세스를 대상으로 실행하는 관리 명령이 아닙니다. Windows의 강제 종료·프로세스 종료 확인은 이 예제의 검증 범위에 포함하지 않습니다.

## 확인할 계약

- 호출 도중 CLI가 종료되면 `calling`을 보존합니다. 이전 CLI 종료를 확인하고 `recover --confirm-stopped`한 뒤 별도 전송 동의로 재호출합니다. 이전 요청이 공급자에게 처리됐는지는 알 수 없으므로 호출 횟수를 되돌리지 않습니다.
- 실행 도중 CLI가 종료되면 연구 세션의 `executing`과 canonical 실험의 `unknown`이 남을 수 있습니다. CLI 종료만으로 실제 실험 프로세스까지 끝났다고 간주하지 않습니다.
- 새 CLI로 상태를 조회하고 `run`을 다시 요청해도 같은 실험을 중복 실행하지 않습니다. 새 확인 근거 없이 실험 결과를 확정하거나 `reconcile`할 수 없습니다.
- 시험용 실행 프로세스의 종료를 확인한 뒤 해당 관측과 파일 해시를 새 근거로 추가합니다. 같은 실험 ID의 기록을 `experiment update`로 갱신하고 `research reconcile`로 관측 단계에 복귀합니다. 이전 근거는 보존합니다.

`recover --confirm-stopped`는 종료 요청이 아닌 사용자의 확인입니다. `reconcile`도 프로세스를 찾아 종료하거나 재실행하지 않습니다. 실제 운영에서는 프로세스·로그·작업 시스템 등에서 근거를 확보해야 하며, PID만으로 종료·성공을 단정하지 않아야 합니다. 이 예제의 시험용 종료 확인 절차를 모든 실행 환경에 적용할 수 있다고 가정하지 마세요.

## 결과 읽기

`summary.json`은 시험 전체 결과와 프로세스 확인 근거, `check`·`status`·호출 측정을 담습니다. `events.json`에는 새 CLI로 수행한 명령과 거부된 요청의 응답이 있고, `checkpoints.json`과 `unknown-experiment.json`으로 종료 직후 상태를 대조할 수 있습니다. `project/recovery-evidence.json`은 실제 시험용 프로세스 관측을 저장하며 canonical 실험 근거에 해시로 연결됩니다.

Linux에서는 시험 하네스가 orphan 자식을 인수해 `waitpid`로 종료 상태를 수집합니다. macOS에서는 자식이 살아 있을 때 등록한 `kqueue`의 종료 이벤트를 확인합니다. macOS에서 이 방식으로 얻지 못한 종료 코드는 미확인으로 남깁니다. 고의로 중단한 시험은 성공 점수로 승격하지 않습니다.

## 검증의 경계

시험용 프로그램은 실행 여부와 종료 확인을 위한 작은 로컬 프로그램이며 ML 성능 검증이 아닙니다. LLM 역할은 루프백 서버의 정해진 응답으로 대체합니다. 실제 공급자의 처리·과금, 분산 작업, 독립적으로 분리된 하위 프로세스, 기록 저장 잠금을 보유한 순간의 강제 종료, 시스템 전체 장애나 전원 손실은 검증하지 않습니다. 예제는 호출 대기 또는 시험용 자식 실행이 확인된 시점에 CLI를 종료하며 잠금 파일을 지워 복구를 우회하지 않습니다.

기록은 승인·관측·근거의 연결을 검사하지만, 사용자가 작성한 확인 내용의 진실성을 자동 판정하지 않습니다. `check`의 경고와 근거 파일을 함께 확인해야 합니다. 기존 [복구 절차](research-api.md#중단과-재개)와 [스킬](../skills/ziho-autoresearch/SKILL.md)을 따릅니다.
