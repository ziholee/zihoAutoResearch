# 완료 세션 반복 조회 비용

2026-10-21 · 개발 소스와 모의 공급자 기준입니다. 실제 API 지연·요금·모델 판단 품질은 검증하지 않습니다.

## 확인한 중복과 변경

기록 100개·완료 세션 1,000개 계획의 [사전 진단](benchmarks/completed-session-profile.json)에서 세션 로드 5,010회의 누적 시간은 1.011초였습니다. 직접 호출한 strict JSON 파싱은 0.506초, 경로 검사는 0.390초, 읽기는 0.088초였습니다. cProfile 오버헤드를 포함한 한 표본이며 이 수치로 실제 개선율을 계산하지 않습니다. 부모·자식 누적 시간은 더하지 않습니다.

`advance` 안에서 과거 세션의 내용 해시와 기억에 필요한 필드만 보관합니다. 매 역할마다 파일 목록을 다시 열거하고 모든 파일의 기존 경로 안전 검사·크기 제한·UTF-8 읽기를 수행합니다. 읽은 텍스트를 UTF-8로 인코딩한 SHA256이 같을 때에만 파싱 결과를 재사용합니다. 크기나 수정 시각만으로 변경 여부를 판단하지 않습니다. 줄바꿈은 기존 `read_text`와 같이 정규화되므로 줄바꿈 형식만 바뀐 경우에는 같은 내용으로 취급합니다.

최대 2,048개 항목, 정규화된 UTF-8 입력 크기 합계 8 MiB까지 보관합니다. 전체 원문이나 파싱된 전체 세션은 보관하지 않습니다. 이 한도는 **프로세스 RSS 상한이 아니며**, Python 객체·현재 읽는 파일·기존 선택 작업 메모리는 별도입니다. 한도 밖 파일도 빠짐없이 읽고 파싱하여 선택에 포함합니다. 파일명 순서로 보관하며 캐시 누락은 속도에만 영향을 줍니다. 삭제된 항목은 다음 조회에서 제거합니다.

기억은 이전과 동일하게 `complete` 상태이며 `memory`가 있는 세션에서 선택합니다. 현재 세션은 제외하고, `created_at` 문자열 오름차순으로 최근 5개를 선택합니다. 같은 시각의 순서는 파일명 순서를 따릅니다. 반환값은 복사하여 호출 측 수정이 캐시를 오염시키지 않습니다. 새 세션·삭제·상태·기억 수정은 다음 역할에 반영되며, 변경된 잘못된 JSON이나 리다이렉트 경로도 기존처럼 거부합니다.

캐시는 한 번의 `advance` 호출에만 존재합니다. 오류·중단·완료로 반환하면 버리고, 새 호출에서는 다시 읽고 파싱합니다. 승인 토큰·검토·실행·중단·unknown 보존·중복 실행 방지·근거 기반 복구 경로는 바꾸지 않습니다. 역할 전후 기록 신선도 검사도 그대로입니다.

## 재현과 측정 범위

```sh
python3.11 scripts/benchmark_research_scale.py --source /path/to/before --output /tmp/session-before --records 100 --sessions 0 100 1000 --repeats 5 --label before
python3.11 scripts/benchmark_research_scale.py --source . --output /tmp/session-after --records 100 --sessions 0 100 1000 --repeats 5 --label after --compare /tmp/session-before/summary.json
```

변경 전은 `70a1d79`입니다. 기존 [규모 측정 도구](research-scale-costs.md)를 수정하지 않고 두 런타임을 고정 복사하여 사용합니다. 각 조건 준비 실행 1회 후 5회 측정하며 변경 전 전체 실행 후 변경 후 전체 실행 순서입니다. 정식 측정 중 테스트·빌드를 병행하지 않습니다. 초기 탐색 측정은 짧은 테스트와 겹쳤으므로 공개 비교에서 제외했습니다. 별도 cProfile 진단과 실측은 구분합니다.

시간에는 Python 시작·import·기존 카운터·CLI·출력·자식의 저장 세션 및 승인 토큰 검증·종료가 포함됩니다. 입력 생성·복사·재개 준비·부모 검증은 제외합니다. RSS는 자식 전체 최고치입니다. 계획은 5개 역할 뒤 승인 대기, 재개는 2개 성공 응답을 저장하고 세 번째 모의 호출에서 중단한 뒤 새 프로세스에서 나머지 3개 역할을 수행합니다. 조회는 기존 승인 대기 세션의 status입니다. 실제 학습·API·프로세스 충돌 복구 성능 측정은 아닙니다.

전후 전체 CLI 의미 해시·최근 기억 순서·역할 순서·예산·승인 토큰 재계산·기록과 이력 원문 보존을 대조합니다. 생성 ID·시간 등의 정규화 기준은 기존 도구와 같습니다. 합성 이력은 7개 역할 출력과 간략한 trace를 포함하므로 실제 큰 응답 이력에 일반화하지 않습니다.

기존 원자료의 `session_loads`는 `research.load` 함수 호출 수입니다. 새 이력 경로는 `_read_session`을 직접 사용하므로 이 수치 감소는 **파일 읽기 감소가 아닙니다**. 별도 회귀에서 계획 중 과거 파일 읽기 5회 유지와 strict 파싱 5→1회를 확인합니다. 캐시에 들어가는 변경 없는 이력의 재개 파싱은 3→1회이며 읽기는 3회 유지합니다. 한도 초과·파일 변경 시 파싱을 다시 수행합니다.

## 검증

독립 기대값으로 최근 5개·동률·상태를 검사하고, 동일 크기·동일 mtime 수정, 추가·삭제·기억·상태 변경, 파싱 오류·큰 파일·심볼릭 링크·잘못된 파일명을 검증합니다. 캐시 항목/바이트 한도를 낮춰도 모든 기억이 선택되며 넘는 항목은 다시 파싱하는지 확인합니다. 실제 모의 루프에서 역할 사이 변경, 중단 후 성공 응답 보존 및 재개, 승인 없는 실행 거부를 확인합니다.

원래 런타임에서 반복 파싱 검사가 5회로 실패하고 변경 후 1회로 통과하는 red/green을 확인했습니다. 실제 API 연결 검증은 보류합니다.

## 정식 측정 결과

Python 3.11.17 · macOS arm64 · 각 조건 5회 중앙값입니다. [변경 전 원자료](benchmarks/completed-session-before.json)와 [변경 후 원자료](benchmarks/completed-session-after.json)에 소스·측정 코드·입력 해시와 개별 표본을 남겼습니다. 아래는 기록 100개를 고정한 세션 축입니다.

| 완료 세션 | 명령 | 시간 전→후 (초) | 감소율 | 최고 RSS 전→후 (MiB) | stdout 전→후 (바이트) |
|---:|---|---:|---:|---:|---:|
| 0 | 계획 | 0.1893 → 0.1850 | 2.3% | 38.58 → 38.73 | 7,586 → 7,587 |
| 0 | 조회 | 0.0889 → 0.0852 | 4.2% | 35.91 → 35.98 | 5,554 → 5,554 |
| 0 | 재개 | 0.1432 → 0.1394 | 2.6% | 38.44 → 38.58 | 5,989 → 5,990 |
| 100 | 계획 | 0.2424 → 0.2218 | 8.5% | 39.06 → 38.94 | 7,588 → 7,587 |
| 100 | 조회 | 0.0887 → 0.0848 | 4.4% | 35.89 → 35.98 | 5,555 → 5,554 |
| 100 | 재개 | 0.1752 → 0.1643 | 6.2% | 38.72 → 38.77 | 5,990 → 5,991 |
| 1,000 | 계획 | 0.7077 → 0.5578 | 21.2% | 44.23 → 41.75 | 7,587 → 7,588 |
| 1,000 | 조회 | 0.0860 → 0.0870 | -1.2% | 35.88 → 36.00 | 5,554 → 5,553 |
| 1,000 | 재개 | 0.4483 → 0.4317 | 3.7% | 42.20 → 41.03 | 5,991 → 5,990 |

1,000개 완료 세션에서 계획 시간은 약 21.2%, 재개는 약 3.7% 감소했습니다. 조회는 캐시를 사용하지 않으며 이번 표본에서는 약 1.2% 느렸습니다. 작은 차이는 환경 변동과 구분할 수 없으므로 모든 명령의 개선을 주장하지 않습니다. 원자료의 기록 축 100개·세션 0개는 기존 도구의 중복 대조 조건으로 함께 보존합니다. 전체 전후 120개 표본에서 CLI 의미·역할·승인·입력 보존 검증이 통과했습니다. stdout은 시각·호출 시간 등 가변 메타데이터 때문에 바이트 수가 조금 다를 수 있습니다.

작은 합성 이력과 따뜻한 파일 캐시에서 얻은 관측값입니다. 실제 큰 이력, 캐시 한도 초과, 다른 파일 시스템·OS·Python, 실제 공급자 지연을 포함한 성능은 별도 검증 대상입니다. 경로 검사·읽기 비용은 남아 있으며 이번 변경은 그것을 생략하지 않습니다.

후속 [큰 세션·캐시 경계 검증](session-cache-boundaries.md)은 큰 본문과 실제 한도 전후를 측정하고, 캐시 밖의 큰 기억 후보를 모두 보관하던 임시 메모리를 줄입니다.
