# LLM 연구 루프 처리 비용 측정

2026-10-19 · 개발 브랜치 구현, 미배포. 실제 모델 호출 없이 모의 응답으로 측정했습니다.

## 바뀐 부분

모델 호출 전 신선도 검사에서 읽은 프로젝트·기록 snapshot을 같은 잠금 구간의 맥락 생성에 재사용합니다. 모델 응답 후에는 디스크에서 다시 읽어 신선도를 검사합니다. 다음 역할·다음 `advance`·프로세스 사이에 snapshot을 캐시하지 않습니다. 부모 실험의 근거 검사도 같은 검사 구간의 snapshot을 사용합니다.

역할에 전달하는 JSON 맥락과 API/Codex 요청 포장의 구분 공백을 제거했습니다. 문자열 안의 공백·소스 코드·근거·숫자 값은 제거하거나 요약하지 않습니다. 응답 검증의 크기 제한과 저장 파일 형식은 변경하지 않았습니다.

분석 → 평가 → 설계 → 구현 제안 → 검토의 5개 호출과 실행 후 해석·기억 2개 호출은 유지합니다. 호출 합치기·역할 생략·자동 재시도·병렬화는 하지 않습니다. 전송 동의, 계획 승인, 명시적 실행, 판단 승인도 같습니다. 따라서 이번 개선은 **로컬 준비 비용과 전송 바이트 감소**이며 모델 호출 횟수 감소가 아닙니다.

## 측정 결과

Python 3.11, macOS arm64에서 각 규모를 한 번 워밍업하고, 새로운 프로세스·합성 프로젝트로 3번씩 측정한 중앙값입니다. 즉시 반환하는 모의 모델을 사용하며 학습 명령은 실행하지 않습니다. 소스·기록 생성과 import 시간은 측정에서 제외합니다. 원본 기준은 `b207c99`입니다.

| 합성 실험 기록 | 계획 5역할 처리 전 → 후 | 로컬 계획 시간 감소 | 맥락 메시지 UTF-8 바이트 전 → 후 | 계획 중 기록 전체 읽기 |
|---|---:|---:|---:|---:|
| 100 | 0.168초 → 0.137초 | 18.2% | 39,603 → 37,397 | 15 → 10 |
| 1,000 | 1.540초 → 1.261초 | 18.1% | 39,643 → 37,437 | 15 → 10 |

시작과 계획을 합친 시간은 각각 0.182초 → 0.151초, 1.666초 → 1.387초였습니다. 모델 호출은 전후 모두 5번이고, 메시지 본문 바이트는 약 5.6% 줄었습니다. 이 바이트 수에는 system/user 본문이 포함되며 HTTP 포장이나 Codex 프로세스 시작 비용은 포함되지 않습니다.

[원본 측정](benchmarks/research-loop-before.json)과 [개선 후 측정](benchmarks/research-loop-after.json)에 개별 시행·역할별 바이트·런타임 소스 해시를 저장했습니다. 실제 모델의 네트워크 지연·생성 시간·토큰 과금·추론 품질은 측정하지 않았습니다. 바이트 감소율을 토큰·요금 절감률이나 실제 전체 루프 속도 향상률로 해석하면 안 됩니다. 대규모 소스나 긴 제안, 많은 완료 세션을 가진 프로젝트에는 별도 측정이 필요합니다.

## 재현

같은 인터프리터로 변경 전후 소스 폴더를 준비해 실행합니다. `--source`는 실행할 zar 코드 경로이며 fixture와 측정 방식은 현재 벤치마크 스크립트가 고정합니다. 출력 파일은 새 경로여야 합니다.

```sh
python3.11 scripts/benchmark_research_loop.py --source /path/to/before --label before --output /tmp/loop-before.json
python3.11 scripts/benchmark_research_loop.py --source . --label after --output /tmp/loop-after.json
```

실제 공급자 검증은 후속입니다. 공급자별로 같은 계획의 호출 수·사용량·지연과 결과 타당성을 비교한 뒤 역할 통합이나 맥락 요약의 효용을 판단해야 합니다.
